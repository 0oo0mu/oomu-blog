## 1. AI/머신러닝/딥러닝의 관계

```
인공지능(AI)
  └─ 머신러닝(Machine Learning) — 데이터로부터 규칙을 "학습"하는 방법
       └─ 딥러닝(Deep Learning) — 인공신경망(뉴럴네트워크)을 이용한 머신러닝
            └─ CNN(합성곱신경망) — 이미지 처리에 특화된 신경망 구조
                 └─ YOLOv8, EfficientNet 등 — 우리가 실제로 쓴 모델들
```

전통적인 프로그래밍은 "규칙을 사람이 직접 코드로 짠다"(if 불량이면... else 정상...)면, 머신러닝은 "정답이 달린 예시 데이터를 많이 보여주고, 컴퓨터가 스스로 규칙(패턴)을 찾아내게 한다"는 접근입니다. 우리가 "용접 불량 사진 1000장 + 정상 사진 1000장"을 모델에게 보여주면서 "이건 불량이야, 이건 정상이야"를 반복 학습시키는 게 바로 이 과정입니다.

## 2. 데이터셋을 나누는 이유 — Train / Validation / Test

학습용 데이터를 그냥 다 학습에 써버리면 안 됩니다. 보통 3개로 나눕니다.

| 이름 | 한국어 | 역할 |
|------|--------|------|
| **Train (학습셋)** | 훈련 데이터 | 모델이 실제로 보고 가중치를 조정하는 데이터 |
| **Validation (검증셋)** | 검증 데이터 | 학습 중간중간 "지금 모델이 얼마나 잘하는지" 확인용 (학습에는 안 씀) |
| **Test (테스트셋)** | 시험 데이터 | 학습이 다 끝난 후 "진짜 실력"을 최종 확인하는 데이터 |

**왜 나누는가?** 시험 문제를 미리 다 외운 학생이 100점을 받았다고 해서 진짜 실력이 좋은 건 아닙니다. 모델도 마찬가지로, 학습에 쓴 데이터로만 평가하면 "외워서 맞히는 것"과 "진짜로 이해해서 맞히는 것"을 구분할 수 없습니다. 그래서 모델이 **한 번도 보지 못한 데이터**로 평가해야 진짜 성능을 알 수 있습니다.

> 이 프로젝트에서 YOLOv8을 학습할 때, Roboflow에서 다운로드한 데이터셋이 이미 `train`/`valid`(또는 `test`) 폴더로 나눠져 있었습니다. 그리고 검사 화면에 넣을 "테스트용 샘플 이미지"를 고를 때도, 일부러 `train` 폴더가 아니라 `test`/`valid` 폴더에서 골랐습니다 — 그래야 "모델이 학습 때 본 적 없는 사진으로 정직하게 테스트"가 되기 때문입니다.

## 3. 과적합(Overfitting)과 과소적합(Underfitting)

이 프로젝트에서 직접 언급된 개념입니다. 모델 학습에서 가장 자주 마주치는 문제입니다.

### 과적합 (Overfitting)

모델이 **학습 데이터를 "이해"하지 않고 "외워버린"** 상태입니다.

- 증상: 학습 데이터에서는 정확도가 99%인데, 검증/테스트 데이터에서는 정확도가 뚝 떨어짐 (예: 학습 정확도 99% vs 검증 정확도 60%)
- 원인: 모델이 너무 복잡하거나(파라미터가 너무 많음), 데이터가 너무 적거나, 너무 오래 학습시켰을 때 발생
- 비유: 기출문제를 통째로 외워서 그 문제는 다 맞히지만, 조금만 바뀐 새 문제가 나오면 못 푸는 학생

### 과소적합 (Underfitting)

반대로, 모델이 **데이터의 패턴을 충분히 배우지 못한** 상태입니다.

- 증상: 학습 데이터에서조차 정확도가 낮음 (학습 60%, 검증도 60% 비슷하게 낮음)
- 원인: 모델이 너무 단순하거나, 학습을 너무 적게 시켰거나, 학습률(learning rate) 설정이 잘못된 경우
- 비유: 공부를 거의 안 해서 기출문제도 잘 못 푸는 상태

```
정확도
  │                         ┌── 학습 정확도
  │                    ┌────┘
  │               ┌────┘
  │          ┌────┘              ← 이 구간 이후로 검증 정확도가 떨어지면 과적합 시작
  │    ┌─────┘  ╲___
  │  ╱           ╲___
  │╱                  ╲___ 검증 정확도
  └──────────────────────────────▶ 학습 진행(epoch)
```

### 어떻게 막는가?

| 방법 | 설명 |
|------|------|
| **데이터 증강(Augmentation)** | 사진을 좌우반전, 회전, 밝기조절 등으로 변형해서 가짜로 데이터 양을 늘림 |
| **조기 종료(Early Stopping)** | 검증 성능이 더 안 좋아지면 학습을 중간에 멈춤 |
| **더 많은 데이터** | 가장 근본적인 해결책 |
| **모델 단순화** | 파라미터가 너무 많은 모델 대신 더 작은 모델 사용 |

> 실제로 09번 글에서 YOLOv8 학습 코드에 `patience=10`이라는 옵션을 넣었는데, 이게 바로 조기 종료(Early Stopping) 설정입니다. "10 epoch 동안 검증 성능이 더 안 좋아지면 그만 학습해라"는 뜻입니다.

## 4. 분류(Classification) vs 탐지(Object Detection)

이 프로젝트에서는 두 가지 종류의 AI 작업을 다 썼습니다.

| | 분류 (Classification) | 객체 탐지 (Object Detection) |
|---|---|---|
| 질문 | "이 사진 전체가 무슨 종류인가?" | "이 사진 안에 무엇이 어디에 있는가?" |
| 출력 | 클래스 하나 (예: "용접") | 박스(위치) + 클래스 여러 개 가능 |
| 이 프로젝트에서 | 카테고리 분류기 (용접/표면/조립 판별) | 불량 위치 탐지 (YOLOv8) |
| 사용 모델 | EfficientNet-B0 | YOLOv8 |

분류는 "사진 한 장 = 라벨 하나"로 비교적 간단하고, 탐지는 "사진 한 장 안에 불량이 0개, 1개, 여러 개 있을 수 있고 각각 위치까지 알아야" 해서 더 복잡한 구조가 필요합니다.

## 5. 정밀도(Precision)와 재현율(Recall) — 가장 중요한 평가지표

모델이 "맞다/틀리다"를 판정할 때, 단순히 "정확도(accuracy)"만으로는 성능을 제대로 평가할 수 없는 경우가 많습니다. 이걸 이해하려면 먼저 4가지 경우를 나눠야 합니다.

|  | 실제로 불량 | 실제로 정상 |
|---|---|---|
| **AI가 "불량"이라고 판정** | TP (True Positive, 맞게 잡음) | FP (False Positive, 헛탕) |
| **AI가 "정상"이라고 판정** | FN (False Negative, 놓침) | TN (True Negative, 맞게 통과시킴) |

- **정밀도(Precision)** = TP / (TP + FP) → "AI가 불량이라고 외친 것 중에서 진짜 불량인 비율" (얼마나 헛소리를 안 하는가)
- **재현율(Recall)** = TP / (TP + FN) → "진짜 불량 중에서 AI가 실제로 잡아낸 비율" (얼마나 놓치지 않는가)

### 왜 둘 다 봐야 하는가?

품질검사처럼 **불량을 놓치면 큰일나는 상황**에서는 재현율(Recall)이 특히 중요합니다. 정밀도만 높이려고 하면(헛탕을 줄이려고 기준을 빡빡하게 잡으면) 진짜 불량을 놓칠 위험(재현율 하락)이 커집니다. 반대로 재현율만 높이려고 기준을 느슨하게 잡으면 정상인데 불량이라고 오탐(정밀도 하락)하는 게 늘어납니다. **둘은 트레이드오프(Trade-off, 하나를 얻으면 하나를 잃는 관계)** 관계입니다.

이 프로젝트의 학습 로그에서 봤던 예시:

```
Class      Box(P      R     mAP50  mAP50-95)
Bad Weld    0.627  0.709    0.66    0.394
Good Weld   0.671  0.726    0.725   0.457
Defect      0.514  0.252    0.36    0.146
```

- `P`(Precision)가 0.514, `R`(Recall)이 0.252인 "Defect" 클래스: 정밀도보다 재현율이 훨씬 낮습니다 — 즉, 실제 Defect 중 25.2%만 잡아내고 나머지는 놓치고 있다는 뜻입니다. 데이터가 다른 클래스보다 적거나 패턴이 더 다양해서 학습이 어려웠다는 신호입니다.

## 6. Confidence (신뢰도)

AI 모델은 "이건 100% 불량이야"라고 딱 잘라 말하지 않고, **0~1 사이의 확률값**으로 "내가 이 판정에 얼마나 확신하는지"를 같이 내놓습니다. 이게 confidence(신뢰도)입니다.

예를 들어 모델이 "confidence 0.83으로 불량"이라고 했다면, "이게 불량일 가능성을 83%로 본다"는 뜻입니다.

이 프로젝트의 백엔드 코드(`real_model.py`)에서는 이 confidence를 가지고 **심각도(severity)**를 규칙으로 나눴습니다.

```python
def _calc_severity_and_action(confidence: float) -> tuple[str, str]:
    if confidence >= 0.90:
        return "불합격", "작업자 육안검사 및 재작업이 필요합니다."
    elif confidence >= 0.75:
        return "재검사", "정밀 재검사를 권장합니다."
    else:
        return "주의", "경미한 의심 소견입니다. 작업 진행 가능하나 추후 모니터링하세요."
```

confidence가 높을수록(모델이 더 확신할수록) 더 심각하게 취급한다는 간단한 규칙입니다. 또한 객체 탐지에서는 **confidence threshold(임계값)**라는 것도 씁니다 — "confidence가 일정 기준(예: 0.35) 미만인 탐지 결과는 너무 불확실하니 그냥 무시한다"는 필터링입니다. `real_model.py`의 `CONF_THRESH = 0.35`가 이 역할을 합니다.

## 7. IoU (Intersection over Union) — 박스가 얼마나 겹치는가

객체 탐지에서 "AI가 그린 박스가 정답 박스와 얼마나 일치하는지"를 재는 지표입니다.

```
IoU = (두 박스가 겹치는 영역의 넓이) / (두 박스를 합친 전체 영역의 넓이)
```

```
   정답 박스          AI가 예측한 박스        겹치는 부분(교집합)
   ┌────────┐          ┌────────┐
   │        │     →    │   ┌────┼───┐
   │        │          │   │////│   │   ← 이 빗금 영역이 "교집합(Intersection)"
   └────────┘          └───┼────┘   │
                            └────────┘
                        전체를 합친 영역이 "합집합(Union)"
```

- IoU = 1.0 → 완벽하게 일치
- IoU = 0.0 → 전혀 안 겹침 (완전히 다른 위치)
- 보통 **IoU ≥ 0.5**면 "맞게 탐지했다"고 인정하는 기준을 많이 씁니다 (이게 바로 다음에 나올 mAP50의 "50"입니다)

## 8. NMS (Non-Maximum Suppression) — 중복 박스 제거

객체 탐지 모델은 같은 불량 하나에 대해 **박스를 여러 개 겹쳐서 예측**하는 경향이 있습니다 (이미지를 작은 격자로 나눠서 각 격자마다 "여기 불량 있는 것 같아?"를 따로 판단하기 때문에, 진짜 불량 하나 주변의 여러 격자가 비슷한 박스를 동시에 그리게 됩니다). NMS는 이 중복을 정리하는 후처리 알고리즘입니다.

알고리즘 동작 방식:
1. confidence가 가장 높은 박스를 하나 선택해서 "확정"으로 남김
2. 그 박스와 IoU가 일정 기준(예: 0.5) 이상으로 많이 겹치는 다른 박스들은 "중복"으로 보고 제거
3. 남은 박스들 중에서 다시 confidence가 가장 높은 것을 선택 → 반복

이 프로젝트의 `real_model.py`에서 직접 구현한 코드:

```python
def _nms(boxes: list, iou_thresh: float = IOU_THRESH) -> list:
    boxes = sorted(boxes, key=lambda b: b["confidence"], reverse=True)
    keep = []
    while boxes:
        best = boxes.pop(0)        # confidence가 가장 높은 박스 하나 뽑기
        keep.append(best)           # 확정 리스트에 추가
        boxes = [b for b in boxes if _iou(best, b) < iou_thresh]  # 많이 겹치는 건 제거
    return keep
```

- `sorted(..., reverse=True)`: confidence 높은 순으로 정렬
- `while boxes:`: 박스가 남아있는 동안 반복
- `boxes.pop(0)`: 맨 앞(가장 높은 confidence)의 박스를 꺼내면서 동시에 리스트에서 제거
- 마지막 줄: "남은 박스 중에 방금 확정한 박스와 IoU가 `iou_thresh` 미만인(별로 안 겹치는) 것들만 남긴다" → 많이 겹치는 중복 박스들은 걸러짐

## 9. mAP — 객체 탐지 모델의 종합 성적표

**mAP(mean Average Precision)**는 객체 탐지 모델의 성능을 하나의 숫자로 요약한 지표입니다. YOLO 학습 로그에 나오는 가장 중요한 숫자입니다.

- **AP(Average Precision)**: 한 클래스에 대해, confidence threshold를 이리저리 바꿔가며 계산한 정밀도-재현율 곡선의 "아래 면적"
- **mAP**: 여러 클래스의 AP를 평균낸 값 (mean = 평균)
- **mAP50**: IoU 기준을 0.5로 뒀을 때의 mAP (즉 "박스가 절반 이상 겹치면 맞다고 쳐준" 기준에서의 점수)
- **mAP50-95**: IoU 기준을 0.5부터 0.95까지 여러 단계로 바꿔가며 평균낸, 더 엄격한 종합 점수

```
mAP50    : 박스 위치가 대략 맞아도 인정 (느슨한 기준)
mAP50-95 : 박스 위치가 거의 정확해야 인정 (엄격한 기준)
```

이 프로젝트에서 실제로 학습한 3개 모델의 결과:

| 모델 | mAP50 | 해석 |
|------|-------|------|
| 용접 결함 탐지 | 0.582 | 절반 이상 정도의 신뢰도로 잘 탐지함 |
| 표면 결함 탐지 | 0.503 | 비슷한 수준 |
| 조립 결함 탐지 | **0.953** | 매우 우수 — 데이터가 더 명확하고 일관된 패턴이었음 |

> **일반적인 기준**: 산업 데이터셋 기준으로 mAP50이 0.5를 넘으면 "그럴듯하게 작동한다"고 볼 수 있고, 0.7~0.9 이상이면 실무에 가까운 수준입니다. 1.0(100%)은 거의 불가능하며, 데이터가 적은 포트폴리오/학습 프로젝트에서 0.5~0.6대도 충분히 의미 있는 결과입니다.

## 10. 전이학습 (Transfer Learning)

이 프로젝트에서 모델을 학습시킬 때, **처음부터(zero) 새로 학습시키지 않고** 이미 다른 대량의 데이터로 미리 학습된 모델(사전학습 모델, pretrained model)에서 시작했습니다.

```python
model = YOLO("yolov8n.pt")   # 이미 COCO 데이터셋으로 학습된 가중치에서 시작
model.train(data="...", epochs=40, ...)
```

```python
model_cat = models.efficientnet_b0(weights=models.EfficientNet_B0_Weights.DEFAULT)  # ImageNet으로 학습된 가중치
```

**왜 이렇게 하는가?** 처음부터 학습시키려면 수백만 장의 이미지와 며칠~몇 주의 GPU 시간이 필요합니다. 반면 이미 "선, 모양, 질감, 색깔" 같은 기본적인 시각 패턴을 학습해 둔 모델을 가져와서, 우리 데이터(용접 사진 수백 장)로 **마지막 부분만 우리 작업에 맞게 미세조정(fine-tuning)**하면, 훨씬 적은 데이터와 시간으로도 좋은 성능을 낼 수 있습니다. 마치 "운전을 전혀 못하는 사람"보다 "오토바이는 잘 타는 사람"에게 자동차 운전을 가르치는 게 더 빠른 것과 비슷한 원리입니다.

이게 가능한 이유는, COCO(일반 사물 80종 인식용 데이터셋)나 ImageNet(사물 1000종 분류용 데이터셋)으로 학습된 모델이라도, "이미지에서 선/모서리/질감 같은 저수준 특징을 뽑아내는 능력" 자체는 용접 사진을 분석하는 데도 어느 정도 재사용할 수 있기 때문입니다.

## 11. Epoch, Batch, Learning Rate, Loss

학습 코드에 등장하는 숫자들의 의미입니다.

```python
model.train(data="...", epochs=40, imgsz=640, batch=16, ...)
```

- **Epoch(에폭)**: 전체 학습 데이터를 한 번 다 훑어보는 것을 1 epoch이라고 합니다. `epochs=40`은 전체 데이터를 40번 반복해서 학습한다는 뜻입니다.
- **Batch(배치)**: 한 번에 모델에 넣어서 학습시키는 데이터 묶음의 크기. `batch=16`이면 16장씩 묶어서 한 번에 처리합니다. (메모리에 한 번에 다 못 올리기 때문에 나눠서 처리하는 것)
- **Learning Rate(학습률)**: 모델이 한 번 학습할 때마다 "얼마나 크게" 가중치를 조정할지 정하는 값. 너무 크면 학습이 불안정해지고(왔다갔다 함), 너무 작으면 학습이 너무 느려집니다.
- **Loss(손실)**: 모델의 예측이 정답과 얼마나 다른지를 나타내는 숫자. 학습이 잘 진행되면 이 숫자가 epoch을 거치면서 점점 줄어듭니다. 학습의 목표는 결국 "이 loss를 최소화하는 것"입니다.

실제 로그에서:

```
Epoch 1/40   box_loss: 2.072   cls_loss: 3.219   dfl_loss: 1.735
...
Epoch 40/40  box_loss: 1.226   cls_loss: 1.177   dfl_loss: 1.237
```

각 loss가 epoch이 진행되면서 점점 줄어드는 것을 볼 수 있습니다 — 모델이 점점 더 정답에 가까워지고 있다는 뜻입니다. (YOLOv8은 박스 위치 오차를 나타내는 `box_loss`, 클래스를 맞추는 `cls_loss`, 박스 경계를 더 정밀하게 다듬는 `dfl_loss` 세 가지를 같이 추적합니다.)

## 12. ONNX — 학습용 모델을 서비스용으로 바꾸기

10번 글에서 자세히 다루지만, 미리 개념만 짚어둡니다.

- **PyTorch**: 모델을 *학습*시킬 때 쓰는 대표적인 프레임워크. 기능이 풍부하지만 무겁고, 학습에 필요한 부가 기능(역전파 계산 등)이 다 들어있어서 무겁습니다.
- **ONNX(Open Neural Network Exchange)**: "이미 학습이 끝난 모델을 가볍게 추론(예측)만 하기 위한 표준 형식"입니다. 학습 기능은 다 떼어내고, 입력을 넣으면 출력만 빠르게 뽑아주는 데 최적화되어 있습니다.

이 프로젝트에서는 Colab(GPU)에서 PyTorch로 학습 → ONNX로 변환 → 가벼운 `onnxruntime` 라이브러리로 Render의 작은 무료 서버에서도 돌아가게 만들었습니다. 비유하면 "요리는 큰 산업용 주방(PyTorch)에서 하고, 완성된 음식만 작은 도시락(ONNX)에 담아서 가져가는 것"과 비슷합니다.

| Epoch/Batch/Loss | 전체 반복 횟수 / 묶음 크기 / 오차 정도 |
| ONNX | 학습 끝난 모델을 가볍게 서비스용으로 변환한 형식 |
