## 1. AI 서버를 호출하는 함수 — `lib/api.ts`

```typescript
// lib/api.ts
// FastAPI AI 서버 호출 함수

import { AIInspectionResult } from "./types";

const AI_API_URL = process.env.NEXT_PUBLIC_AI_API_URL || "http://localhost:8000";

/**
 * 이미지를 FastAPI 서버로 전송하고 AI 분석 결과를 받습니다.
 * 검사종류(용접/표면/조립)는 AI가 사진을 보고 자동으로 판별합니다.
 */
export async function inspectImage(file: File): Promise<AIInspectionResult> {
  const formData = new FormData();
  formData.append("image", file);

  const response = await fetch(`${AI_API_URL}/inspect`, {
    method: "POST",
    body: formData,
  });

  if (!response.ok) {
    const error = await response.json().catch(() => ({}));
    throw new Error(error.detail || "AI 서버 오류가 발생했습니다.");
  }

  return response.json();
}

/**
 * AI 서버 상태 확인
 */
export async function checkAIHealth(): Promise<boolean> {
  try {
    const response = await fetch(`${AI_API_URL}/health`, { signal: AbortSignal.timeout(3000) });
    return response.ok;
  } catch {
    return false;
  }
}
```

### 뜯어보기

#### `new FormData()`
일반적인 JSON 요청(`{"key": "value"}`)으로는 **파일**을 보낼 수 없습니다. 파일을 전송할 때는 `FormData`라는 특수한 형식을 씁니다 — 우리가 HTML에서 `<input type="file">`로 파일을 첨부해서 폼을 제출할 때 브라우저가 내부적으로 쓰는 바로 그 형식입니다.

```typescript
formData.append("image", file);
```

"`image`라는 이름(key)으로 이 파일을 첨부한다"는 뜻입니다. 이 이름은 05번 글에서 본 FastAPI 코드의 `async def inspect_image(image: UploadFile = File(...))`의 파라미터 이름(`image`)과 정확히 일치해야 합니다 — 이름이 안 맞으면 서버가 파일을 못 찾습니다.

#### `fetch(url, { method: "POST", body: formData })`
**fetch**는 브라우저(자바스크립트)에서 네트워크 요청을 보내는 표준 함수입니다. `body`에 `FormData`를 넣으면 브라우저가 자동으로 적절한 `Content-Type` 헤더(`multipart/form-data; boundary=...`)를 붙여줍니다 — 직접 헤더를 지정할 필요가 없습니다 (오히려 직접 지정하면 boundary 값이 빠져서 에러가 날 수 있습니다).

#### `if (!response.ok) { ... throw new Error(...) }`
`fetch`는 서버가 404나 500 에러를 응답해도 **자바스크립트 에러를 던지지 않습니다** (네트워크 자체가 실패했을 때만 에러를 던짐). 그래서 `response.ok`(상태 코드가 200번대인지)를 직접 확인해서, 실패했으면 우리가 직접 에러를 만들어 던져야(`throw`) 합니다. 이렇게 해야 호출하는 쪽에서 `try/catch`로 에러를 잡을 수 있습니다.

`.catch(() => ({}))`: 에러 응답의 JSON을 파싱하다가 또 실패할 경우(응답이 JSON이 아닐 수도 있으니), 빈 객체로 대체해서 추가 에러가 안 나게 방어합니다.

#### `AbortSignal.timeout(3000)`
"3000ms(3초) 안에 응답이 없으면 요청을 자동으로 취소한다"는 설정. 헬스체크처럼 빨리 끝나야 하는 요청에 타임아웃을 걸어두면, 서버가 응답을 안 줄 때 화면이 영원히 기다리는 상황을 막을 수 있습니다.

## 2. 검사종류·불량유형 공통 데이터 — `lib/inspectionMeta.ts`

여러 화면(검사 요청, 검사 이력, 통계)에서 똑같이 쓰는 "검사종류 한글명", "불량유형 한글명", "심각도 색상" 같은 데이터를 한 파일에 모아뒀습니다.

```typescript
// lib/inspectionMeta.ts
export type InspectionCategory = "welding" | "surface" | "assembly";

export const CATEGORY_LIST: InspectionCategory[] = ["welding", "surface", "assembly"];

export const categoryLabel: Record<InspectionCategory, string> = {
  welding: "용접부 외관 검사",
  surface: "부품 표면 검사",
  assembly: "조립 상태 검사",
};

export const defectTypesByCategory: Record<InspectionCategory, DefectOption[]> = {
  welding: [
    { value: "crack", label: "균열" },
    { value: "undercut", label: "언더컷" },
    // ... (생략)
  ],
  // ...
};

// 전체 불량 유형 코드 → 한국어 라벨 (검사종류 구분 없이 한번에 찾을 때 사용)
export const defectTypeKr: Record<string, string> = Object.values(defectTypesByCategory)
  .flat()
  .reduce((acc, d) => ({ ...acc, [d.value]: d.label }), {} as Record<string, string>);

export function getDefectLabel(code: string | null | undefined): string {
  if (!code) return "—";
  return defectTypeKr[code] ?? code;
}
```

### 왜 이렇게 한 파일로 모아뒀는가? (DRY 원칙)

처음에는 각 컴포넌트(`InspectionForm`, `InspectionDetail`, `InspectionList`, `StatsDashboard`)마다 자기만의 `defectTypeKr` 객체를 따로 갖고 있었습니다. 그런데 검사종류를 3가지(용접/표면/조립)로 확장하면서 불량 유형이 5개에서 16개로 늘어나자, **4개 파일을 일일이 찾아다니며 똑같은 수정을 반복**해야 하는 문제가 생겼습니다.

이런 상황을 피하기 위한 원칙이 **DRY(Don't Repeat Yourself, 같은 것을 반복하지 마라)**입니다. 공통으로 쓰이는 데이터/로직은 한 곳에 모아두고, 다른 곳에서는 그걸 가져다(import) 쓰기만 하면, 나중에 수정할 일이 생겼을 때 **딱 한 곳만 고치면** 모든 화면에 자동으로 반영됩니다.

#### `Object.values(객체).flat().reduce(...)` — 데이터 변환 체이닝

```typescript
Object.values(defectTypesByCategory)   // [[용접배열], [표면배열], [조립배열]]
  .flat()                               // [용접1, 용접2, ..., 표면1, ..., 조립1, ...]  (배열의 배열을 평평하게 펼침)
  .reduce((acc, d) => ({ ...acc, [d.value]: d.label }), {})  // { crack: "균열", rust: "녹·부식", ... }
```

- **`Object.values(객체)`**: 객체의 모든 "값"들만 배열로 뽑아냄 (키는 버림)
- **`.flat()`**: 배열 안에 배열이 들어있는 "2단 배열"을 한 단계 펼쳐서 1단 배열로 만듦
- **`.reduce(누적함수, 초기값)`**: 배열을 순회하면서 하나의 결과값으로 "누적"해 나가는 함수. 여기서는 빈 객체 `{}`에서 시작해서, 각 항목을 `{ [d.value]: d.label }` 형태로 계속 합쳐 나갑니다 (`{ ...acc, ... }`로 기존 누적값을 펼치고 새 키를 추가).

이렇게 한 번 변환해두면, "용접 카테고리의 불량인지 표면 카테고리의 불량인지" 따로 신경 쓰지 않고 **코드 어디서든 `defectTypeKr["crack"]`으로 바로 "균열"을 꺼낼 수** 있습니다.

## 3. 검사 요청 페이지 — Server Component

```tsx
// app/inspections/new/page.tsx
import { createServerSupabaseClient } from "@/lib/supabase-server";
import InspectionForm from "@/components/inspections/InspectionForm";
import { Ship, Block } from "@/lib/types";

export default async function NewInspectionPage() {
  const supabase = createServerSupabaseClient();
  const { data: { user } } = await supabase.auth.getUser();

  const [{ data: ships }, { data: blocks }] = await Promise.all([
    supabase.from("ships").select("id, name, ship_type").order("name"),
    supabase.from("blocks").select("id, ship_id, block_name, process_type").order("block_name"),
  ]);

  return (
    <div className="space-y-6 max-w-2xl">
      <div>
        <h1 className="text-2xl font-bold text-slate-800">AI 검사 요청</h1>
        <p className="text-slate-500 text-sm mt-1">
          검사할 선박·블록을 선택하고 이미지를 업로드하면 AI가 정상/불량을 판정합니다.
        </p>
      </div>
      <InspectionForm
        ships={(ships as Ship[]) ?? []}
        blocks={(blocks as Block[]) ?? []}
        userId={user?.id ?? ""}
      />
    </div>
  );
}
```

### `Promise.all([...])` — 동시에 여러 요청 보내기

```typescript
const [{ data: ships }, { data: blocks }] = await Promise.all([
  supabase.from("ships").select(...),
  supabase.from("blocks").select(...),
]);
```

선박 목록과 블록 목록은 서로 의존하지 않는 독립적인 데이터입니다. 이런 경우 `await A; await B;`처럼 순서대로(직렬로) 기다리면 "A 끝날 때까지 기다렸다가 그 다음에 B 시작"이 되어 두 번의 대기 시간이 더해집니다. `Promise.all([A, B])`로 묶으면 **두 요청을 동시에 보내고, 둘 다 끝날 때까지만** 기다리므로 전체 시간이 더 짧아집니다 (둘 중 더 오래 걸리는 것의 시간만큼만 기다림).

`[{ data: ships }, { data: blocks }]`는 **배열 구조분해할당(destructuring)**입니다. `Promise.all`의 결과는 `[결과1, 결과2]` 형태의 배열인데, 각 결과 객체에서 `data` 속성만 바로 꺼내서 `ships`, `blocks`라는 이름으로 받습니다.

## 4. 테스트용 샘플 이미지 API — `app/api/samples/route.ts`

매번 다른 사진을 찾아서 업로드하기 번거로워서, **서버의 `public/samples` 폴더에 미리 넣어둔 사진 목록을 읽어서 알려주는 작은 API**를 만들었습니다.

```typescript
// app/api/samples/route.ts
import { NextResponse } from "next/server";
import fs from "fs";
import path from "path";

const CATEGORIES = ["welding", "surface", "assembly"] as const;
const IMAGE_EXT = [".jpg", ".jpeg", ".png", ".webp"];

export async function GET() {
  const result: Record<string, string[]> = {};

  for (const cat of CATEGORIES) {
    const dir = path.join(process.cwd(), "public", "samples", cat);
    try {
      const files = fs
        .readdirSync(dir)
        .filter((f) => IMAGE_EXT.includes(path.extname(f).toLowerCase()));
      result[cat] = files;
    } catch {
      result[cat] = []; // 폴더가 없으면 빈 배열
    }
  }

  return NextResponse.json(result);
}
```

### 이게 왜 가능한가? — Route Handler

`app/api/samples/route.ts`처럼 `app` 폴더 안에 `route.ts`(또는 `route.js`) 파일을 만들면, Next.js는 이걸 **API 엔드포인트**로 취급합니다. `page.tsx`가 화면(HTML)을 반환하는 거라면, `route.ts`는 데이터(JSON)를 반환하는 작은 서버 함수입니다. `export async function GET()`이라는 이름으로 함수를 만들면 "이 주소에 GET 요청이 오면 이 함수를 실행하라"는 의미가 됩니다.

이 코드는 **Server Component나 백엔드 코드에서만 쓸 수 있는 Node.js의 `fs`(파일시스템) 모듈**을 사용합니다 — 브라우저에서는 보안상 컴퓨터의 파일을 직접 읽을 수 없지만, Next.js 서버는 자기 서버에 있는 파일 목록을 읽을 수 있습니다. `fs.readdirSync(폴더경로)`는 그 폴더 안의 모든 파일/폴더 이름을 배열로 돌려줍니다.

```typescript
.filter((f) => IMAGE_EXT.includes(path.extname(f).toLowerCase()))
```

`path.extname("photo.JPG")`는 `.JPG`를 반환합니다. `.toLowerCase()`로 소문자로 통일한 다음, 우리가 원하는 이미지 확장자 목록에 들어있는지 확인해서, 혹시 폴더에 다른 파일(예: 텍스트 파일)이 섞여 있어도 걸러냅니다.

```typescript
try { ... } catch { result[cat] = []; }
```

해당 카테고리 폴더가 아직 안 만들어져 있으면 `readdirSync`가 에러를 던지는데, 이걸 잡아서 그냥 빈 배열로 처리합니다 — 폴더가 없다고 전체 API가 깨지면 안 되니까요.

## 5. 검사 요청 폼 전체 코드 — `InspectionForm.tsx`

이제 가장 핵심적인 파일입니다. 전체 코드를 먼저 보고, 그 다음 부분별로 자세히 설명합니다.

```tsx
"use client";
// components/inspections/InspectionForm.tsx
// 검사 요청 폼 - 선박/블록 선택 → 이미지 업로드 → AI 분석(검사종류 자동판별) → 결과 저장

import { useState, useRef, useCallback, useEffect } from "react";
import { useRouter } from "next/navigation";
import { createClient } from "@/lib/supabase";
import { inspectImage } from "@/lib/api";
import { Ship, Block, AIInspectionResult, Severity } from "@/lib/types";
import {
  categoryLabel, categoryShortLabel, severityColor, getDefectLabel,
} from "@/lib/inspectionMeta";
import {
  Upload, X, Loader2, CheckCircle, AlertTriangle,
  ChevronDown, ImageIcon, Sparkles
} from "lucide-react";

interface Props {
  ships: Ship[];
  blocks: Block[];
  userId: string;
}

// 단계 정의
type Step = "form" | "analyzing" | "result";

const SAMPLES_PER_CATEGORY = 3;
const SAMPLE_CATEGORIES = ["welding", "surface", "assembly"] as const;

// 배열에서 n개를 무작위로 뽑기
function pickRandom<T>(arr: T[], n: number): T[] {
  const copy = [...arr];
  for (let i = copy.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [copy[i], copy[j]] = [copy[j], copy[i]];
  }
  return copy.slice(0, n);
}

export default function InspectionForm({ ships, blocks, userId }: Props) {
  const router   = useRouter();
  const supabase = createClient();
  const fileInputRef = useRef<HTMLInputElement>(null);

  const [step, setStep]           = useState<Step>("form");
  const [selectedShip, setSelectedShip] = useState("");
  const [selectedBlock, setSelectedBlock] = useState("");
  const [memo, setMemo]           = useState("");
  const [imageFile, setImageFile] = useState<File | null>(null);
  const [imagePreview, setImagePreview] = useState<string>("");
  const [dragging, setDragging]   = useState(false);
  const [aiResult, setAiResult]   = useState<AIInspectionResult | null>(null);
  const [savedId, setSavedId]     = useState<string>("");
  const [error, setError]         = useState("");
  const [sampleImages, setSampleImages] = useState<{ path: string; label: string }[]>([]);

  // 선택된 선박에 속한 블록만 필터링
  const filteredBlocks = blocks.filter((b) => b.ship_id === selectedShip);

  // ── 테스트용 샘플 이미지 목록 불러오기 ──
  useEffect(() => {
    fetch("/api/samples")
      .then((res) => res.json())
      .then((data: Record<string, string[]>) => {
        const picked: { path: string; label: string }[] = [];
        for (const cat of SAMPLE_CATEGORIES) {
          const files = data[cat] ?? [];
          const chosen = pickRandom(files, SAMPLES_PER_CATEGORY);
          chosen.forEach((f) => {
            picked.push({ path: `/samples/${cat}/${f}`, label: categoryShortLabel[cat] });
          });
        }
        setSampleImages(picked);
      })
      .catch(() => setSampleImages([]));
  }, []);

  // ── 이미지 선택 처리 ──────────────────────────────
  function handleFile(file: File) {
    if (!file.type.startsWith("image/")) {
      setError("이미지 파일만 업로드 가능합니다.");
      return;
    }
    if (file.size > 10 * 1024 * 1024) {
      setError("파일 크기는 10MB 이하여야 합니다.");
      return;
    }
    setError("");
    setImageFile(file);
    setImagePreview(URL.createObjectURL(file));
  }

  const onDrop = useCallback((e: React.DragEvent) => {
    e.preventDefault();
    setDragging(false);
    const file = e.dataTransfer.files[0];
    if (file) handleFile(file);
  }, []);

  // ── 샘플 이미지 클릭 시 자동으로 업로드 처리 (테스트용) ──
  async function handleSampleClick(path: string) {
    try {
      const res = await fetch(path);
      const blob = await res.blob();
      const fileName = path.split("/").pop() || "sample.jpg";
      const file = new File([blob], fileName, { type: blob.type || "image/jpeg" });
      handleFile(file);
    } catch {
      setError("샘플 이미지를 불러오지 못했습니다.");
    }
  }

  // ── AI 검사 실행 ──────────────────────────────────
  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    if (!imageFile) { setError("이미지를 업로드해 주세요."); return; }
    if (!selectedShip) { setError("선박을 선택해 주세요."); return; }
    if (!selectedBlock) { setError("블록을 선택해 주세요."); return; }

    setError("");
    setStep("analyzing");

    try {
      // 1. FastAPI AI 서버에 이미지 전송
      const result = await inspectImage(imageFile);
      setAiResult(result);

      // 2. Supabase Storage에 이미지 업로드
      const ext       = imageFile.name.split(".").pop();
      const fileName  = `${Date.now()}_${Math.random().toString(36).slice(2)}.${ext}`;
      const filePath  = `inspections/${fileName}`;

      const { error: uploadError } = await supabase.storage
        .from("inspections")
        .upload(filePath, imageFile, { contentType: imageFile.type });

      if (uploadError) throw new Error("이미지 업로드 실패: " + uploadError.message);

      // 3. 이미지 공개 URL 가져오기
      const { data: urlData } = supabase.storage
        .from("inspections")
        .getPublicUrl(filePath);

      // 4. 검사 결과 DB 저장
      const { data: inspection, error: dbError } = await supabase
        .from("inspections")
        .insert({
          ship_id:             selectedShip,
          block_id:            selectedBlock,
          user_id:             userId,
          image_url:           urlData.publicUrl,
          result:              result.result,
          defect_type:         result.defect_type,
          confidence:          result.confidence,
          status:              "pending",
          inspection_category: result.inspection_category,
          severity:            result.severity,
          recommended_action:  result.recommended_action,
          memo:                memo || null,
        })
        .select()
        .single();

      if (dbError) throw new Error("검사 결과 저장 실패: " + dbError.message);

      // 5. 불량 위치 박스 저장 (defect_logs)
      if (result.defect_boxes.length > 0 && inspection) {
        await supabase.from("defect_logs").insert(
          result.defect_boxes.map((box) => ({
            inspection_id: inspection.id,
            bbox_x:        box.x,
            bbox_y:        box.y,
            bbox_width:    box.width,
            bbox_height:   box.height,
            label:         box.label,
            confidence:    box.confidence,
          }))
        );
      }

      setSavedId(inspection?.id ?? "");
      setStep("result");

    } catch (err: any) {
      setError(err.message || "오류가 발생했습니다.");
      setStep("form");
    }
  }

  // ── 결과 화면 ─────────────────────────────────────
  if (step === "result" && aiResult) {
    const isDefect = aiResult.result === "defect";
    const severity = aiResult.severity as Severity | null;
    return (
      <div className="space-y-4">
        <div className={`rounded-2xl border-2 p-6 ${isDefect ? "border-red-200 bg-red-50" : "border-green-200 bg-green-50"}`}>
          <div className="flex items-center gap-1.5 mb-3 text-xs text-slate-500">
            <Sparkles className="w-3.5 h-3.5 text-blue-500" />
            AI 자동 판별: <strong className="text-slate-700">{categoryLabel[aiResult.inspection_category]}</strong>
            <span className="text-slate-400">({(aiResult.category_confidence * 100).toFixed(0)}%)</span>
          </div>

          <div className="flex items-center gap-4 mb-4">
            {isDefect ? <AlertTriangle className="w-10 h-10 text-red-500" /> : <CheckCircle className="w-10 h-10 text-green-500" />}
            <div className="flex-1">
              <div className="flex items-center gap-2">
                <p className={`text-2xl font-bold ${isDefect ? "text-red-700" : "text-green-700"}`}>
                  {isDefect ? "불량 감지" : "정상"}
                </p>
                {severity && (
                  <span className={`text-xs font-semibold px-2.5 py-1 rounded-full border ${severityColor[severity]}`}>
                    {severity}
                  </span>
                )}
              </div>
              <p className="text-sm text-slate-500 mt-0.5">
                신뢰도: <strong>{(aiResult.confidence * 100).toFixed(1)}%</strong>
                {isDefect && aiResult.defect_type && (
                  <span className="ml-2">· 불량 유형: <strong>{getDefectLabel(aiResult.defect_type)}</strong></span>
                )}
              </p>
            </div>
          </div>

          {aiResult.recommended_action && (
            <div className="mb-4 px-4 py-2.5 bg-white/70 border border-slate-200 rounded-lg text-sm text-slate-700">
              <span className="font-semibold">권장 조치: </span>{aiResult.recommended_action}
            </div>
          )}

          {imagePreview && (
            <div className="relative rounded-xl overflow-hidden bg-slate-100 aspect-video">
              <img src={imagePreview} alt="검사 이미지" className="w-full h-full object-contain" />
              {aiResult.defect_boxes.map((box, i) => (
                <div
                  key={i}
                  className="absolute border-2 border-red-500 bg-red-500/10"
                  style={{
                    left:   `${(box.x - box.width  / 2) * 100}%`,
                    top:    `${(box.y - box.height / 2) * 100}%`,
                    width:  `${box.width  * 100}%`,
                    height: `${box.height * 100}%`,

                </div>
              ))}
            </div>
          )}
        </div>

        <div className="flex gap-3">
          <button onClick={() => router.push(`/inspections/${savedId}`)} className="flex-1 py-3 bg-blue-600 hover:bg-blue-700 text-white rounded-xl font-medium text-sm">
            결과 상세 보기
          </button>
          <button
            onClick={() => { setStep("form"); setAiResult(null); setImageFile(null); setImagePreview(""); setMemo(""); }}
            className="flex-1 py-3 border border-slate-300 text-slate-700 hover:bg-slate-50 rounded-xl font-medium text-sm"
          >
            새 검사 요청
          </button>
        </div>
      </div>
    );
  }

  // ── 분석 중 화면 ──────────────────────────────────
  if (step === "analyzing") {
    return (
      <div className="flex flex-col items-center justify-center py-20 space-y-4">
        <Loader2 className="w-12 h-12 text-blue-600 animate-spin" />
        <p className="text-lg font-semibold text-slate-700">AI 분석 중...</p>
        <p className="text-sm text-slate-400">검사종류 판별 및 불량 여부를 분석하고 있습니다. 잠시만 기다려 주세요.</p>
        <div className="w-48 bg-slate-200 rounded-full h-1.5 overflow-hidden">
          <div className="h-full bg-blue-600 rounded-full animate-pulse w-3/4" />

    );
  }

  // ── 검사 폼 ───────────────────────────────────────
  return (
    <form onSubmit={handleSubmit} className="space-y-5">
      {error && <div className="p-3 bg-red-50 border border-red-200 rounded-lg text-sm text-red-600">{error}</div>}

            <label className="block text-xs font-medium text-slate-600 mb-1.5">선박 <span className="text-red-500">*</span></label>
            <div className="relative">
              <select
                value={selectedShip}
                onChange={(e) => { setSelectedShip(e.target.value); setSelectedBlock(""); }}
                required

                <option value="">선박 선택</option>

            <div className="relative">
              <select

                onChange={(e) => setSelectedBlock(e.target.value)}
                required
                disabled={!selectedShip}
                className="w-full px-3 py-2.5 border border-slate-300 rounded-lg text-sm appearance-none focus:outline-none focus:ring-2 focus:ring-blue-500 disabled:bg-slate-50 disabled:text-slate-400"
```

## 6. 핵심 부분 한 줄씩 뜯어보기

### 화면을 3단계로 나누는 상태 머신

```tsx
type Step = "form" | "analyzing" | "result";
const [step, setStep] = useState<Step>("form");
```

이 컴포넌트는 하나의 컴포넌트 안에서 **"입력 폼" → "분석 중" → "결과"** 세 가지 화면을 전환합니다. 코드 구조도 이를 그대로 반영합니다:

```tsx
if (step === "result" && aiResult) { return (...결과 화면...); }
if (step === "analyzing") { return (...분석 중 화면...); }
return (...입력 폼...);  // 마지막 기본값
```

세 화면이 전혀 다른 페이지처럼 보이지만, 사실은 **하나의 컴포넌트가 `step` 값에 따라 다른 JSX를 반환할 뿐**입니다. 이런 패턴을 "유한 상태 기계(Finite State Machine)"라고 부르기도 하는데, 거창한 이름이지만 "지금 어떤 상태인지에 따라 다르게 행동한다"는 단순한 아이디어입니다.

### `useRef`로 숨겨진 파일 입력창 제어하기

```tsx
const fileInputRef = useRef<HTMLInputElement>(null);
...
<input ref={fileInputRef} type="file" accept="image/*" className="hidden" ... />
...
onClick={() => fileInputRef.current?.click()}
```

**useRef**는 "리렌더링되어도 값이 유지되지만, 값이 바뀌어도 화면을 다시 그리지는 않는" 특수한 상자입니다. 여기서는 실제 HTML `<input type="file">` 엘리먼트를 가리키는 용도로 씁니다.

기본 파일 선택 버튼(`<input type="file">`)은 디자인을 마음대로 꾸미기 어렵습니다. 그래서 실제 `<input>`은 `className="hidden"`(화면에서 안 보이게)으로 숨기고, 대신 예쁘게 디자인한 드래그앤드롭 영역을 클릭하면 `fileInputRef.current?.click()`으로 **숨겨진 input을 코드로 대신 클릭**시켜서 원래의 파일 선택 창을 열게 만듭니다. 사용자에게는 예쁜 영역을 클릭한 것처럼 보이지만, 실제로는 표준 파일 선택 기능이 그대로 동작합니다.

### 드래그 앤 드롭

```tsx
const onDrop = useCallback((e: React.DragEvent) => {
  e.preventDefault();
  setDragging(false);
  const file = e.dataTransfer.files[0];
  if (file) handleFile(file);
}, []);
```

```tsx
<div
  onDragOver={(e) => { e.preventDefault(); setDragging(true); }}
  onDragLeave={() => setDragging(false)}
  onDrop={onDrop}
  ...
>
```

- **`onDragOver`**: 파일을 끌고 영역 위에 올라왔을 때 계속 발생하는 이벤트. `e.preventDefault()`를 안 해주면 브라우저가 기본 동작(파일을 새 탭에서 열기 등)을 해버려서 우리가 만든 드롭 영역이 작동하지 않습니다.
- **`onDragLeave`**: 영역을 벗어나면 `dragging` 상태를 다시 꺼서 테두리 강조를 없앱니다.
- **`onDrop`**: 실제로 파일을 놓은 순간. `e.dataTransfer.files`에 떨어뜨려진 파일들이 들어있습니다.
- **`useCallback(함수, [])`**: 이 함수를 매 렌더링마다 새로 만들지 않고 재사용하게 해주는 Hook입니다. (성능 최적화 목적이며, 이 컴포넌트 규모에서는 큰 차이는 없지만 좋은 습관입니다.)

### 파일 유효성 검사와 미리보기

```tsx
function handleFile(file: File) {
  if (!file.type.startsWith("image/")) {
    setError("이미지 파일만 업로드 가능합니다.");
    return;
  }
  if (file.size > 10 * 1024 * 1024) {
    setError("파일 크기는 10MB 이하여야 합니다.");
    return;
  }
  setError("");
  setImageFile(file);
  setImagePreview(URL.createObjectURL(file));
}
```

- `file.size > 10 * 1024 * 1024`: 파일 크기는 바이트(byte) 단위입니다. 1024바이트 = 1KB, 1024KB = 1MB이므로 `10 * 1024 * 1024`는 10MB를 바이트로 환산한 값입니다.
- **`URL.createObjectURL(file)`**: 아직 서버에 업로드하지 않은, 사용자 컴퓨터에만 있는 파일을 **브라우저 메모리 안에서 임시 URL**로 만들어주는 함수입니다. 이 URL을 `<img src={...}>`에 넣으면 서버에 올리기 전에도 미리보기를 보여줄 수 있습니다. (참고: 이 URL은 임시적인 것이라 페이지를 떠나면 사라집니다.)

### 샘플 이미지 클릭 → 가짜 File 객체 만들기

```tsx
async function handleSampleClick(path: string) {
  try {
    const res = await fetch(path);
    const blob = await res.blob();
    const fileName = path.split("/").pop() || "sample.jpg";
    const file = new File([blob], fileName, { type: blob.type || "image/jpeg" });
    handleFile(file);
  } catch {
    setError("샘플 이미지를 불러오지 못했습니다.");
  }
}
```

원래 `handleFile`은 "사용자가 직접 고른 파일(File 객체)"을 받는 함수입니다. 샘플 이미지는 사용자가 직접 고른 게 아니라 **서버 폴더에 미리 있는 이미지 URL**입니다. 이걸 같은 함수로 처리하기 위해, **URL → 바이너리(Blob) → File 객체로 변환**하는 과정을 거칩니다.

- `fetch(path)`: 이미지 URL에 요청을 보내서 실제 이미지 파일 데이터를 받아옴
- `res.blob()`: 응답 본문을 **Blob**(Binary Large Object, 이미지/동영상 같은 이진 데이터를 다루는 자바스크립트 객체)으로 변환
- `new File([blob], 파일명, { type: ... })`: `File`은 `Blob`을 한 단계 더 감싼 것으로, 파일명과 타입 정보를 추가로 가집니다. 이렇게 만든 `file`은 사용자가 직접 `<input type="file">`로 고른 파일과 **완전히 똑같이 동작**합니다 — 그래서 같은 `handleFile` 함수로 그대로 처리할 수 있습니다.

이 기법(URL을 다시 File 객체로 되돌리는 것)은 "이미 서버에 있는 파일을, 사용자가 새로 고른 것처럼 업로드 로직에 재사용하고 싶을 때" 자주 쓰는 패턴입니다.

### 전체 제출 흐름 — `handleSubmit`

```
1. 유효성 검사 (이미지, 선박, 블록 다 선택했는지)
2. AI 서버에 이미지 전송 → 결과 받기
3. Supabase Storage에 원본 이미지 업로드
4. 그 이미지의 공개 URL 받기
5. inspections 테이블에 결과 저장 (이미지 URL 포함)
6. 불량 박스가 있으면 defect_logs 테이블에도 저장
7. 결과 화면으로 전환
```

이 순서가 중요한 이유: **AI 분석을 먼저 하고, 그 다음에 이미지를 저장**합니다. 만약 순서를 바꿔서 이미지부터 저장했는데 AI 분석이 실패하면, "쓸모없는 이미지만 저장소에 남고 검사 기록은 없는" 상태가 됩니다. 지금 순서대로 하면, AI 분석이 실패한 경우 아예 아무것도 저장되지 않아서 데이터 일관성이 유지됩니다.

```tsx
const ext       = imageFile.name.split(".").pop();
const fileName  = `${Date.now()}_${Math.random().toString(36).slice(2)}.${ext}`;
```

- `imageFile.name.split(".").pop()`: 파일명을 `.`(점)으로 나눈 배열의 마지막 원소 = 확장자 (예: `"photo.jpg".split(".")`는 `["photo", "jpg"]`, `.pop()`은 마지막 원소를 꺼내서 `"jpg"`를 반환)
- `Date.now()`: 1970년 1월 1일부터 지금까지의 밀리초(ms) 수. 시간이 지날수록 항상 더 큰 숫자가 되므로, 파일명이 충돌할 가능성이 거의 없습니다.
- `Math.random().toString(36).slice(2)`: 0~1 사이 무작위 소수를 36진법 문자열로 바꾸고, 앞의 `"0."` 부분을 잘라내서 무작위 글자 조합을 만듦. 이건 같은 밀리초에 동시에 두 명이 업로드해도 파일명이 겹치지 않게 하는 추가 안전장치입니다.

```tsx
const { data: urlData } = supabase.storage.from("inspections").getPublicUrl(filePath);
```

`upload()`는 파일을 저장소에 올리기만 하고 URL을 안 줍니다. 업로드가 성공한 뒤, **이 파일이 실제로 인터넷에서 접근 가능한 주소가 무엇인지**는 `getPublicUrl()`로 별도로 물어봐야 합니다. (Storage 버킷을 "Public"으로 설정해뒀기 때문에 이 URL로 누구나 이미지를 볼 수 있습니다 — 01번 글 참고)

### 박스 위치를 화면에 그리는 방법

```tsx
<div
  className="absolute border-2 border-red-500 bg-red-500/10"
  style={{
    left:   `${(box.x - box.width  / 2) * 100}%`,
    top:    `${(box.y - box.height / 2) * 100}%`,
    width:  `${box.width  * 100}%`,
    height: `${box.height * 100}%`,
  }}
>
```

05번 글에서 박스 좌표를 "중심점(x, y) + 너비/높이"의 비율(0~1)로 저장한다고 했습니다. CSS의 `left`/`top`은 "박스의 좌상단 모서리" 위치를 기준으로 그려야 하므로, **중심점에서 너비/높이의 절반을 빼서 좌상단 좌표로 변환**하는 계산이 필요합니다.

```
center_x = 0.5, width = 0.2 라면
left = 0.5 - 0.2/2 = 0.4   →  "40%"
```

부모 엘리먼트(이미지를 감싸는 `<div>`)에 `className="relative"`가 있고, 이 박스에 `className="absolute"`가 있는 게 핵심입니다. CSS에서 `absolute`로 위치를 지정한 엘리먼트는, 가장 가까운 `relative`(또는 다른 위치 지정) 조상 엘리먼트를 기준으로 좌표가 계산됩니다. 그래서 이미지 위에 정확히 겹쳐서 박스가 그려집니다.

이번 글의 핵심 개념:
