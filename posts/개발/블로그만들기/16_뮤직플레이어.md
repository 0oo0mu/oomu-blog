# 뮤직 플레이어

10편에서 "SPA를 쓰는 이유는 음악이 안 끊기게 하기 위해서"라고 했죠. 이번 편에서 그 뮤직 플레이어를 만듭니다. 이 파일은 실제로 590줄로 시리즈에서 가장 길지만, **핵심 아이디어**만 잡으면 나머지는 그 반복입니다. (전체 코드는 완성된 저장소의 `js/modules/music-player.js`를 참고하세요. 여기선 뼈대와 핵심을 다룹니다.)

## 오디오의 정체 — Audio 객체

브라우저는 소리를 내는 **Audio** 객체를 기본 제공합니다. 화면에 안 보이는 오디오 플레이어예요.

```javascript
const audio = new Audio();
audio.src = 'music/song.mp3';  // 재생할 파일
audio.play();                  // 재생
audio.pause();                 // 정지
audio.volume = 0.7;            // 볼륨 (0~1)
audio.currentTime = 30;        // 30초 지점으로 이동
```

그리고 오디오는 여러 **이벤트**를 발생시킵니다.

- `loadedmetadata` — 곡 정보(길이 등)를 다 읽었을 때
- `timeupdate` — 재생 위치가 바뀔 때(프로그레스 바 갱신용)
- `ended` — 곡이 끝났을 때(다음 곡으로)

이 이벤트들을 구독해 UI를 갱신하는 게 플레이어의 뼈대입니다.

## playlist.json — 곡 목록

곡 목록은 `music/playlist.json`에 둡니다. (06편 build.js가 `music` 폴더를 스캔해 자동 생성하게 만들 수도 있어요.)

```json
[
  { "title": "On My Own", "artist": "Darci", "file": "music/song1.mp3" },
  { "title": "외부 곡",   "artist": "someone", "file": "https://example.com/x.mp3" }
]
```

로컬 파일(`music/*.mp3`)이든 외부 URL이든 `file`에 넣으면 됩니다.

## 뼈대 — music-player.js (핵심만)

`js/modules/music-player.js`의 핵심 골격입니다.

```javascript
import Storage from '../core/storage.js';

const MusicPlayer = {
  audio: null,
  playlist: [],
  currentIndex: 0,
  isPlaying: false,

  async init() {
    // 1) 곡 목록 로드
    try {
      const res = await fetch('music/playlist.json');
      this.playlist = res.ok ? await res.json() : [];
    } catch { this.playlist = []; }

    // 2) 오디오 객체 + 화면(하단 바) 만들기
    this.audio = new Audio();
    this._buildDOM();     // 하단 바 HTML을 body에 삽입 (생략: 저장소 참고)
    this._bindEvents();   // 버튼/오디오 이벤트 연결
    this._restoreState(); // ★ 이전 페이지의 재생 상태 복원

    // 3) 페이지 떠날 때 상태 저장
    window.addEventListener('beforeunload', () => this._saveState());
  },

  _togglePlay() {
    if (this.playlist.length === 0) return;
    if (this.isPlaying) { this.audio.pause(); this.isPlaying = false; }
    else {
      if (!this.audio.src) this._loadTrack(this.currentIndex, false);
      this.audio.play();
      this.isPlaying = true;
    }
    this._updatePlayBtn();
  },

  _loadTrack(index, autoPlay = true) {
    const n = this.playlist.length;
    this.currentIndex = ((index % n) + n) % n;   // 범위 보정(음수·초과 처리)
    this.audio.src = this.playlist[this.currentIndex].file;
    this.audio.load();
    Storage.set('mp_index', this.currentIndex);
    if (autoPlay) this.audio.play();
  },

  _next() { this._loadTrack(this.currentIndex + 1, this.isPlaying); },
  _prev() {
    if (this.audio.currentTime > 3) { this.audio.currentTime = 0; return; }
    this._loadTrack(this.currentIndex - 1, this.isPlaying);
  },

  // ★ 상태 저장/복원 — SPA에서 음악이 안 끊기는 핵심
  _saveState() {
    Storage.set('mp_index', this.currentIndex);
    Storage.set('mp_time',  this.audio.currentTime);
    Storage.set('mp_volume', this.audio.volume);
  },
  _restoreState() {
    this.audio.volume = Storage.get('mp_volume', 0.7);
    const idx = Storage.get('mp_index', 0);
    if (this.playlist.length) this._loadTrack(Math.min(idx, this.playlist.length - 1), false);
    // 복원된 재생 위치는 loadedmetadata 이벤트에서 적용:
    //   audio.currentTime = Storage.get('mp_time', 0);
  },
};

export default MusicPlayer;
```

전체 파일은 여기에 더해 **셔플/반복/볼륨/프로그레스 바/플레이리스트 패널** UI를 붙인 것뿐입니다. 원리는 위와 같아요.

## 왜 SPA라야 음악이 안 끊길까 (이 파일의 존재 이유)

일반 멀티페이지 방식이라면, 글을 클릭할 때마다 `post.html`로 **페이지가 통째로 새로 로드**됩니다. 그 순간 **Audio 객체도 파괴**되어 음악이 뚝 끊기죠. 우리가 10편에서 SPA를 만든 진짜 이유가 이겁니다 — **페이지를 새로 안 열고 내용만 바꾸니, 하단 플레이어와 Audio 객체가 그대로 살아 있어** 음악이 계속됩니다.

그런데 사용자가 **주소를 직접 치거나, standalone `post.html`로 들어오거나, 새로고침(F5)** 하면 어쩔 수 없이 페이지가 새로 로드됩니다. 이때를 대비한 게 **상태 저장/복원**이에요.

- `beforeunload`(페이지 떠나기 직전) 이벤트에서 `_saveState()` → 현재 곡·재생 위치·볼륨을 localStorage에 저장
- 새 페이지 진입 시 `_restoreState()` → 저장된 상태를 불러와 **같은 곡, 같은 지점**부터 이어서 준비 (단, 자동 재생은 안 함 — 브라우저가 사용자 동작 없는 자동재생을 막기 때문)

즉 SPA 안에선 애초에 안 끊기고, 어쩔 수 없이 페이지가 바뀌어도 상태를 복원해 최대한 자연스럽게 이어줍니다.

## 알아둘 것 — 자동재생 정책 & 무한 인덱스

- **자동재생 차단**: 브라우저는 사용자가 클릭 한 번 하기 전엔 소리 재생을 막습니다(광고 소음 방지). 그래서 복원 시 곡만 준비해두고, 재생은 사용자가 ▶를 눌러야 시작돼요. `audio.play()`가 실패할 수 있어 `.catch()`로 감쌉니다.
- **인덱스 순환**: `((index % n) + n) % n` — 다음/이전 곡에서 인덱스가 끝을 넘거나 음수가 돼도 목록 안으로 **빙 돌게** 만드는 공식입니다. 마지막 곡 다음은 첫 곡, 첫 곡 이전은 마지막 곡이 되죠.

## 연결

진입점에서 등록합니다. (모든 페이지에서 동작하도록 index/post 양쪽에.)

```javascript
import MusicPlayer from './modules/music-player.js';
App.register('music', MusicPlayer);   // init() 자동 호출
```

## 정리

- 브라우저 **Audio** 객체로 소리를 재생하고, `loadedmetadata`·`timeupdate`·`ended` 이벤트로 UI를 갱신한다.
- 곡 목록은 `music/playlist.json`(로컬·외부 URL 모두 지원).
- **SPA라서** 페이지 전환에도 Audio가 살아 음악이 안 끊긴다. 새로고침 등 불가피한 경우엔 **localStorage 저장/복원**으로 이어준다.
- 자동재생은 브라우저가 막으므로 사용자 클릭 후 재생.
