# 배포 자동화 + 마무리

드디어 마지막 편입니다. 지금까지는 배포할 때마다 `node build.js`를 손으로 돌렸죠. 이번 편에서 **push만 하면 자동으로 빌드·배포**되게 만들고, `build.js`가 SEO 파일까지 챙기게 확장한 뒤, 20편의 여정을 정리합니다.

## build.js 확장 — 부가 파일 자동 생성

06편의 `build.js`에 함수 몇 개를 더합니다. 각각 파일을 하나씩 만들어요.

```javascript
// sitemap.xml — 검색엔진에 "이런 글들이 있어요" 알려주는 지도
function generateSitemap(posts) {
  const { siteUrl } = config;
  if (!siteUrl) return; // 사이트 주소 설정 전이면 건너뜀
  const urls = posts.map(p => `  <url>
    <loc>${siteUrl}/post.html?file=${encodeURIComponent(p.file)}</loc>
    <lastmod>${p.date}</lastmod>
  </url>`).join('\n');
  const xml = `<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
${urls}
</urlset>`;
  fs.writeFileSync(path.join(__dirname, 'sitemap.xml'), xml, 'utf-8');
}

// robots.txt — 크롤러 규칙
function generateRobots() {
  fs.writeFileSync(path.join(__dirname, 'robots.txt'),
    'User-agent: *\nAllow: /\n', 'utf-8');
}

// js/core/config.js — blog.config.json을 프론트엔드에서 쓰게 변환
function generateFrontendConfig() {
  const js = `const Config = ${JSON.stringify(config, null, 2)};\nexport default Config;\n`;
  fs.writeFileSync(path.join(__dirname, 'js', 'core', 'config.js'), js, 'utf-8');
}
```

- **sitemap.xml** — 검색엔진(구글 등)에 글 목록을 알려주는 지도. 검색 노출에 도움.
- **robots.txt** — 크롤러에게 "여기는 봐도 돼" 같은 규칙을 알려주는 파일.
- **config.js** — `blog.config.json`(사이트 이름·주소 등)을 프론트엔드 자바스크립트가 `import`할 수 있게 변환해 자동 생성. 그래서 설정을 한 곳(`blog.config.json`)에서만 관리합니다.

메인 실행부 끝에 호출을 추가합니다.

```javascript
fs.writeFileSync(OUTPUT, JSON.stringify(posts, null, 2), 'utf-8');
generateSitemap(posts);
generateRobots();
generateFrontendConfig();
console.log('[Build] 완료');
```

## 빈 폴더도 카테고리로 — .gitkeep 자동 생성

13편에서 "글 없는 빈 폴더도 카테고리로 보이게" 했었죠. 그런데 **Git은 빈 폴더를 저장소에 안 올립니다.** 그래서 build.js가 빈 폴더마다 `.gitkeep`이라는 빈 파일을 넣어 폴더가 저장소에 남게 합니다. 그리고 모든 폴더 목록을 `categories.json`으로 내보내 사이드바·에디터가 씁니다.

```javascript
function findCategoryDirs(dir, baseDir = dir) {
  const dirs = [];
  for (const entry of fs.readdirSync(dir, { withFileTypes: true })) {
    if (entry.isDirectory()) {
      const full = path.join(dir, entry.name);
      dirs.push(path.relative(baseDir, full).replace(/\\/g, '/'));
      dirs.push(...findCategoryDirs(full, baseDir));
    }
  }
  return dirs;
}

const categoryDirs = findCategoryDirs(POSTS_DIR);
// 파일 없는 빈 폴더에 .gitkeep 생성 (git이 폴더를 추적하도록)
categoryDirs.forEach(rel => {
  const abs = path.join(POSTS_DIR, rel);
  const hasFile = fs.readdirSync(abs, { withFileTypes: true }).some(e => e.isFile());
  if (!hasFile) fs.writeFileSync(path.join(abs, '.gitkeep'), '', 'utf-8');
});
fs.writeFileSync(path.join(POSTS_DIR, 'categories.json'),
  JSON.stringify(categoryDirs, null, 2), 'utf-8');
```

## 자동 배포 — GitHub Actions

지금은 `deploy.bat`이 로컬에서 build를 돌린 뒤 push합니다. 더 나은 방법은 **push만 하면 GitHub이 알아서 build를 돌리고 배포**하는 것. 이걸 **GitHub Actions**(CI: 자동화 도구)로 합니다.

저장소에 `.github/workflows/deploy.yml` 파일을 만드세요.

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]      # main에 push되면 실행
  workflow_dispatch:       # 수동 실행도 가능

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true   # 진행 중이던 배포는 취소 (멈춘 배포 정리)

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: node build.js            # ★ CI에서 빌드
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with: { path: . }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

- `on: push` — main 브랜치에 push될 때마다 이 워크플로우가 자동 실행됩니다.
- `build` 잡: 우분투 컴퓨터를 하나 빌려(runner) 코드를 받고, Node를 깔고, **`node build.js`를 실행**해 posts.json 등을 만든 뒤, 사이트 전체를 배포용으로 업로드합니다.
- `deploy` 잡: 업로드된 걸 GitHub Pages에 게시합니다.
- `concurrency: cancel-in-progress` — 배포가 겹치거나 멈추는 걸 막아줍니다.

이걸 쓰면 **저장소 Settings → Pages → Source를 "GitHub Actions"로** 바꿔야 합니다. 이후엔:

```bash
git add .
git commit -m "새 글"
git push
```

**push만 하면** GitHub이 build부터 배포까지 자동으로 합니다. 로컬에서 build를 깜빡해도 CI가 최신으로 만들어줘요. (19편 웹 에디터의 "게시"도 결국 이 push를 일으켜 자동 배포로 이어집니다.)

## 20편의 여정 — 우리가 만든 것

축하합니다. 정말 밑바닥부터 여기까지 왔습니다. 돌아보면 이만큼을 만들었어요.

- **기초**(01~03): 개발 환경, HTML 뼈대, CSS 변수 디자인 시스템
- **콘텐츠**(04~07): 마크다운 렌더링, 글 불러오기, 빌드 스크립트, GitHub 무료 배포
- **구조**(08): 이벤트 버스 — 모듈을 느슨하게 잇는 심장
- **핵심 화면**(09~11): 카드 목록, SPA 라우터, 필터(카테고리·태그·검색·정렬)
- **경험**(12~15): 다크 모드·색상 테마, 사이드바 트리, 검색·목차, 코드 하이라이팅·토글
- **화려함**(16~17): 안 끊기는 뮤직 플레이어, D3 연결 그래프
- **글쓰기**(18~19): 웹 에디터, GitHub 게시·수정·삭제, 비밀번호 잠금
- **자동화**(20): SEO 파일 생성, GitHub Actions 자동 배포

무엇보다, **"왜 이렇게 만드는지"**를 하나하나 짚으며 왔습니다. 이벤트 버스로 결합도를 낮추는 이유, SPA로 음악을 안 끊는 이유, CSS 변수로 테마를 바꾸는 이유, 토큰을 암호화하는 이유 — 이 "왜"가 남는다면 이 시리즈는 성공입니다.
