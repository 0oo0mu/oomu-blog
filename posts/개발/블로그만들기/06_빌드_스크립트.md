# 빌드 스크립트

글이 하나면 지난 편처럼 이름을 직접 적어 불러오면 됩니다. 그런데 글이 30개면요? 목록을 손으로 관리할 순 없죠. 이번 편에서 **글 폴더를 자동으로 훑어 목록을 만들어주는 작은 프로그램** `build.js`를 만듭니다.

## 왜 빌드가 필요할까 — 브라우저의 한계

핵심 사실 하나를 알아야 합니다.

> **브라우저(그 안의 자바스크립트)는 폴더 안에 어떤 파일이 있는지 스스로 알 수 없습니다.**

보안 때문입니다. 자바스크립트가 "이 폴더에 파일 목록 보여줘" 할 수 있으면 위험하니까 막혀 있어요. 그래서 브라우저는 **정확한 파일 이름을 알아야만** `fetch`할 수 있습니다. 지난 편에서 `first.md`처럼 이름을 콕 집었던 이유죠.

그럼 글이 여러 개일 때 목록은 어떻게 만들까요? 답:

> 미리 **내 컴퓨터에서** 폴더를 훑어서 **"글 목록표"** 파일 하나(`posts.json`)를 만들어 둔다. 브라우저는 그 목록표만 `fetch`하면 전체 글을 알 수 있다.

이렇게 **배포 전에 미리 준비 작업을 하는 것**을 **빌드(build)**라고 합니다. 그 준비 작업을 하는 프로그램이 `build.js`예요.

## Node.js — 브라우저 밖에서 자바스크립트 실행

브라우저는 폴더를 못 읽지만, **Node.js**는 읽을 수 있습니다. Node는 브라우저 밖(내 컴퓨터)에서 자바스크립트를 실행하는 도구라, 파일을 읽고 쓰는 권한이 있거든요.

Node에서 파일을 다루려면 **모듈**을 불러옵니다.

```javascript
const fs   = require('fs');    // file system: 파일 읽기/쓰기
const path = require('path');  // 경로(폴더/파일 주소) 다루기
```

- `require('fs')` — Node에 기본 내장된 **파일 시스템** 도구. `readFileSync`(읽기), `writeFileSync`(쓰기), `readdirSync`(폴더 목록) 등을 씁니다.
- `require('path')` — 경로를 안전하게 조합하는 도구. 윈도우(`\`)와 맥(`/`)의 경로 차이도 알아서 처리해줘요.

> 브라우저에서 파일을 나눌 땐 `import`/`export`를 썼는데, Node의 기본 방식은 `require`입니다. 둘 다 "다른 코드 가져오기"지만 문법이 다릅니다. `build.js`는 Node로 돌리니 `require`를 씁니다.

## 설정 파일 만들기 — blog.config.json

먼저 사이트 이름 같은 설정을 담을 파일을 `Blog` 폴더에 `blog.config.json`으로 만듭니다.

```json
{
  "siteName": "내 블로그",
  "siteUrl": "",
  "description": "개발과 일상을 기록하는 블로그",
  "author": "무"
}
```

**JSON**은 데이터를 적는 형식입니다. `"이름": 값` 쌍을 중괄호로 묶어요. 자바스크립트 객체와 거의 똑같이 생겼습니다. (주의: JSON에선 키를 꼭 큰따옴표로 감싸고, 맨 마지막 항목 뒤에 쉼표를 붙이면 안 됩니다.)

## 실제 파일 — build.js (핵심 버전)

`Blog` 폴더에 `build.js`를 만들고 아래를 넣으세요. 이 블로그 실제 `build.js`의 **핵심 뼈대**입니다. (뒤 편에서 카테고리·사이트맵 등을 여기에 붙여 나갑니다.)

```javascript
const fs   = require('fs');
const path = require('path');

// ── 설정 읽기 ──
const configPath = path.join(__dirname, 'blog.config.json');
const config = fs.existsSync(configPath)
  ? JSON.parse(fs.readFileSync(configPath, 'utf-8'))
  : { siteName: 'My Blog', siteUrl: '', description: '', author: '' };

const POSTS_DIR = path.join(__dirname, 'posts');
const OUTPUT    = path.join(POSTS_DIR, 'posts.json');

// ── posts 폴더를 재귀적으로 훑어 .md 파일 경로를 모두 모으기 ──
function findMarkdownFiles(dir, baseDir = dir) {
  const entries = fs.readdirSync(dir, { withFileTypes: true });
  const files   = [];

  for (const entry of entries) {
    const fullPath = path.join(dir, entry.name);
    if (entry.isDirectory()) {
      // 폴더면 그 안으로 다시 들어가 훑는다 (재귀)
      files.push(...findMarkdownFiles(fullPath, baseDir));
    } else if (entry.isFile() && entry.name.endsWith('.md')) {
      const rel = path.relative(baseDir, fullPath).replace(/\\/g, '/');
      files.push(rel);
    }
  }
  return files;
}

// ── Front Matter 파싱 (markdown.js의 것과 같은 원리) ──
function parseFrontMatter(raw) {
  const meta  = {};
  const match = raw.match(/^---\n([\s\S]*?)\n---\n([\s\S]*)$/);
  if (!match) return { meta, content: raw };

  match[1].split('\n').forEach(line => {
    const colonIdx = line.indexOf(':');
    if (colonIdx === -1) return;
    const key = line.slice(0, colonIdx).trim();
    const val = line.slice(colonIdx + 1).trim();
    if (key === 'tags') {
      meta.tags = val.replace(/[\[\]]/g, '').split(',').map(t => t.trim()).filter(Boolean);
    } else {
      meta[key] = val;
    }
  });
  return { meta, content: match[2] };
}

// ── 카테고리 자동 추출: 파일 경로의 폴더 부분 ──
function extractCategory(relPath) {
  const parts = relPath.split('/');
  parts.pop();               // 파일명 제거
  return parts.join('/');    // 남은 폴더 경로가 카테고리
}

// ── 요약 자동 생성: 본문에서 마크다운 기호 걷어내고 앞 150자 ──
function generateExcerpt(content, maxLen = 150) {
  const plain = content
    .replace(/^#+\s+/gm, '')                 // 헤딩 기호 제거
    .replace(/[*_`>~]/g, '')                 // 강조/코드 기호 제거
    .replace(/\[([^\]]+)\]\([^)]+\)/g, '$1')  // 링크 → 글자만
    .replace(/\n+/g, ' ')                    // 줄바꿈 → 공백
    .trim();
  return plain.length > maxLen ? plain.slice(0, maxLen) + '...' : plain;
}

// ── 메인 실행 ──
const mdFiles = findMarkdownFiles(POSTS_DIR);
const posts = [];

for (const relPath of mdFiles) {
  const raw = fs.readFileSync(path.join(POSTS_DIR, relPath), 'utf-8');
  const { meta, content } = parseFrontMatter(raw);

  const title    = meta.title    || path.basename(relPath, '.md');
  const category = meta.category || extractCategory(relPath);
  const excerpt  = meta.excerpt  || generateExcerpt(content);

  posts.push({
    file: relPath,
    title,
    date: meta.date || '',
    category,
    tags: meta.tags || [],
    excerpt,
  });
}

// 최신 글이 먼저 오도록 날짜 내림차순 정렬
posts.sort((a, b) => new Date(b.date) - new Date(a.date));

fs.writeFileSync(OUTPUT, JSON.stringify(posts, null, 2), 'utf-8');
console.log('posts/posts.json 생성됨 (' + posts.length + '개 글)');
```

## 실행해보기

터미널(VS Code 터미널)에서 `Blog` 폴더에 있는지 확인하고, 이렇게 칩니다.

```bash
node build.js
```

`posts/posts.json 생성됨 (1개 글)` 같은 메시지가 뜨고, `posts` 폴더에 **`posts.json`** 파일이 새로 생깁니다. 열어보면 이런 내용이에요.

```json
[
  {
    "file": "first.md",
    "title": "나의 첫 글",
    "date": "2026-07-14",
    "category": "",
    "tags": ["블로그", "시작"],
    "excerpt": "드디어 파일로 쓴 글이 화면에 떴다! 마크다운으로 쓰고..."
  }
]
```

각 글의 정보가 목록으로 정리됐죠. **브라우저는 이제 이 파일 하나만 fetch하면 전체 글을 다 알 수 있습니다.**

## 한 부분씩 해설

- **`__dirname`** — "이 `build.js` 파일이 있는 폴더"를 뜻하는 Node 특수 변수. `path.join(__dirname, 'posts')`로 posts 폴더의 정확한 경로를 만듭니다.
- **`findMarkdownFiles`** — 폴더를 훑는 함수인데, 폴더 안에 폴더가 있으면 **자기 자신을 다시 호출**해서 더 깊이 들어갑니다. 이렇게 함수가 자신을 부르는 걸 **재귀(recursion)**라고 해요. 덕분에 `posts/개발/블로그/글.md`처럼 몇 겹으로 중첩된 폴더도 전부 찾아냅니다. `.replace(/\\/g, '/')`는 윈도우 경로의 역슬래시(`\`)를 슬래시(`/`)로 바꿔 통일하는 처리입니다.
- **`extractCategory`** — 파일 경로에서 파일명만 떼면 남는 폴더 경로가 곧 카테고리입니다. 그래서 **글을 어느 폴더에 두느냐가 곧 카테고리**가 돼요. (Front Matter에 `category`를 직접 적으면 그게 우선합니다: 메인 실행부의 `meta.category || extractCategory(...)`가 그 뜻 — 앞이 있으면 앞을, 없으면 뒤를 씀.)
- **`generateExcerpt`** — 요약(`excerpt`)을 안 적었을 때, 본문에서 기호를 걷어내고 앞 150자를 잘라 자동으로 만들어줍니다. `.replace(...)`가 여러 번 나오는데 각각 특정 마크다운 기호를 지우는 정규식이에요.
- **메인 루프** — 찾은 `.md`들을 하나씩 읽어 정보/본문으로 나누고, `{ file, title, date, category, tags, excerpt }` 객체로 만들어 `posts` 배열에 담습니다. `||`(또는)는 **"앞이 비어 있으면 뒤 값을 쓴다"**는 뜻이라, 제목을 안 적었으면 파일명을, 카테고리를 안 적었으면 폴더 경로를 자동으로 씁니다.
- **정렬** — `posts.sort((a, b) => new Date(b.date) - new Date(a.date))`로 날짜를 최신순(내림차순)으로 줄 세웁니다.
- **저장** — `JSON.stringify(posts, null, 2)`는 배열을 보기 좋은 JSON 글자로 바꾸고(`null, 2`는 들여쓰기 2칸), `fs.writeFileSync`로 `posts.json` 파일에 씁니다.

## 앞으로의 리듬

이제 **글을 쓰거나 고친 뒤에는 `node build.js`를 한 번 돌려** 목록을 갱신하는 습관이 생깁니다. (나중에 배포 자동화에서 이걸 자동으로 돌게 만들 거예요.)

## 자주 나는 실수

- **`Cannot find module 'fs'`류 에러** → Node가 아니라 브라우저에서 돌리려 했을 때. `build.js`는 반드시 터미널에서 `node build.js`로 실행합니다.
- **`posts.json`이 안 생김 / 0개** → `posts` 폴더 위치가 맞는지, `.md` 파일이 그 안에 있는지 확인. 터미널이 `Blog` 폴더에 있는지도 확인.
- **JSON 문법 에러(blog.config.json)** → 키는 큰따옴표, 마지막 항목 뒤 쉼표 금지.
- **글 고쳤는데 사이트에 반영 안 됨** → `node build.js`를 다시 안 돌렸거나, 브라우저 새로고침을 안 함.

## 정리

- 브라우저는 폴더 목록을 못 보므로, **Node로 미리 훑어 `posts.json`(목록표)을 만든다** = 빌드.
- Node에선 `require('fs')`, `require('path')`로 파일을 다룬다.
- `build.js`는 posts 폴더를 **재귀**로 훑고, 각 `.md`의 Front Matter를 파싱해 목록을 만들고, 날짜순 정렬 후 `posts.json`으로 저장한다.
- 폴더 구조가 곧 카테고리가 된다.
- 글 작업 후엔 `node build.js`.
