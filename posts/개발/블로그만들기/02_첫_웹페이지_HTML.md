# 첫 웹페이지 만들기

이번 편에서 만드는 것: **내가 쓴 글자가 브라우저에 뜨는 페이지 하나.** 결과물은 작아 보이지만, 앞으로 만들 모든 것이 여기서 자라납니다. 그래서 이번 편은 천천히, 깊게 갑니다.

## 잠깐 — 웹페이지가 대체 뭘까?

많은 사람이 "웹사이트 = 인터넷 저 너머 어딘가에 있는 신비한 것"이라고 생각합니다. 사실은 훨씬 시시합니다.

**웹페이지는 그냥 파일입니다.** `.txt` 메모장 파일처럼, 글자가 적힌 파일이에요. 확장자만 `.html`일 뿐입니다.

그럼 브라우저(크롬 같은 것)는 뭘까요? **브라우저는 그 파일을 읽어서 화면에 그림으로 그려주는 프로그램**입니다. 요리로 치면 `.html` 파일은 "레시피"이고, 브라우저는 그 레시피대로 요리를 만들어 접시에 담아주는 요리사예요.

여기서 중요한 사실 하나:

> 웹페이지를 보려고 꼭 인터넷이나 서버가 필요한 건 아닙니다. **내 컴퓨터에 있는 `.html` 파일을 브라우저로 그냥 열 수 있습니다.**

우리는 당분간 인터넷 없이, 내 컴퓨터 안에서 파일을 만들고 브라우저로 열어보며 진행합니다. 인터넷에 올리는(배포) 건 한참 뒤(07편)의 일입니다.

## HTML의 정체

**HTML**은 HyperText Markup Language의 약자인데, 약자는 잊어도 됩니다. 하는 일만 기억하세요.

> HTML은 **"이 자리에는 제목, 저기에는 문단, 여기에는 목록"** 하고 웹페이지의 **구조(뼈대)**를 적는 언어입니다.

집을 짓는다고 상상해봅시다. 웹페이지를 만드는 데는 보통 세 가지가 협력합니다.

- **HTML** — 벽·문·창문의 위치를 잡는 **뼈대**
- **CSS** — 벽지·페인트·조명 같은 **꾸밈** (다음 편)
- **자바스크립트(JS)** — 스위치를 누르면 불이 켜지는 **동작** (더 뒤)

이번 편은 오직 **뼈대(HTML)**만 다룹니다. 그래서 결과물이 흑백에 밋밋해도 정상입니다. 꾸미는 건 다음 편에서 합니다.

## HTML의 기본 단위 — 태그, 요소, 속성

HTML은 **태그(tag)**라는 표시로 이루어집니다. 태그는 꺾쇠 `< >`로 감쌉니다.

```html
<h1>큰 제목</h1>
```

이 한 줄을 분해하면:

- `<h1>` — **여는 태그**. "여기서부터 큰 제목이야"
- `큰 제목` — **내용**. 실제로 화면에 보일 글자
- `</h1>` — **닫는 태그**. `/`(슬래시)가 붙으면 "여기서 끝"이라는 뜻

이렇게 **여는 태그 + 내용 + 닫는 태그**를 한 덩어리로 묶은 것을 **요소(element)**라고 부릅니다. 앞으로 "h1 요소", "p 요소"처럼 말할 거예요.

태그 이름은 대부분 영어 약자입니다. 몇 개만 미리 봅시다.

- `h1` ~ `h6` — heading. 제목. 숫자가 작을수록 큰 제목 (`h1`이 제일 큼)
- `p` — paragraph. 문단
- `ul` / `li` — unordered list / list item. 점(•) 목록과 그 항목
- `a` — anchor. 링크
- `img` — image. 이미지

### 속성(attribute) — 태그에 붙이는 옵션

태그에는 추가 정보를 붙일 수 있습니다. 이걸 **속성**이라고 합니다. 여는 태그 안에 `이름="값"` 형태로 씁니다.

```html
<a href="https://google.com">구글로 가기</a>
```

- `a` — 링크 요소
- `href="https://google.com"` — **속성**. "이 링크를 누르면 이 주소로 가"라는 옵션 (href = hypertext reference)
- `구글로 가기` — 화면에 보일 글자

속성은 "이 요소를 어떻게 다룰지"를 세밀하게 정해주는 옵션이라고 생각하면 됩니다.

### 혼자 닫는 태그

대부분의 태그는 여는 태그와 닫는 태그가 짝을 이루지만, **내용이 없는 태그**도 있습니다. 예를 들어 이미지는 "여기에 그림 하나" 하고 끝이라 감쌀 내용이 없어요.

```html
<img src="cat.png" />
```

이런 건 `</img>`를 따로 안 쓰고, 끝을 `/>`로 혼자 닫습니다. (`src`는 source, 그림 파일 위치를 가리키는 속성입니다.)

## 이제 진짜로 만들어봅시다 — index.html

웹사이트의 첫 화면 파일은 관례적으로 **`index.html`**로 짓습니다. 왜 하필 `index`일까요?

> 브라우저와 웹 서버 사이에는 오래된 약속이 있습니다. "어떤 폴더에 들어왔는데 정확한 파일 이름을 안 줬으면, `index.html`을 대신 보여줘라." 그래서 대문 역할을 하는 파일에 `index`라는 이름을 붙입니다.

만드는 법:

1. VS Code 왼쪽에서 `Blog` 폴더 이름 위에 마우스를 올리면 아이콘 몇 개가 나타납니다. **새 파일**(문서에 + 표시) 아이콘을 클릭.
2. 파일 이름을 정확히 `index.html`로 입력하고 엔터. (대소문자·오타 주의 — `Index.html`이나 `index.htm`은 다른 파일 취급될 수 있어요.)
3. 오른쪽에 빈 편집 창이 열립니다. 여기에 아래 코드를 그대로 씁니다.

```html
<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8" />
  <title>내 블로그</title>
</head>
<body>
  <h1>안녕, 블로그</h1>
  <p>이건 내가 만든 첫 웹페이지야.</p>
</body>
</html>
```

다 썼으면 **Ctrl+S**(맥은 Cmd+S)로 저장하세요. 저장 안 하면 브라우저에 반영이 안 됩니다. 파일 이름 옆에 하얀 동그라미(●)가 보이면 "저장 안 됨" 표시예요.

## 한 줄씩, 아주 자세히

이 뼈대는 앞으로 만들 모든 페이지에 똑같이 들어갑니다. 그러니 지금 확실히 이해하고 넘어갑시다.

### `<!DOCTYPE html>`

문서 맨 첫 줄에 딱 한 번 쓰는 선언입니다. "이 문서는 최신 HTML 규칙을 따를 거야"라고 브라우저에 알려주는 신호예요. 옛날에는 이 줄이 엄청 길고 복잡했는데, 지금은 이렇게 짧아졌습니다. 이유는 몰라도 되고, **맨 위에 그냥 이렇게 쓴다**만 기억하세요.

### `<html lang="ko">` … `</html>`

문서 전체를 감싸는 **가장 바깥 요소**입니다. 모든 내용이 이 안에 들어갑니다.

`lang="ko"`는 "이 문서는 한국어야"라는 속성입니다. 검색엔진이나 번역기, 화면 읽어주는 프로그램이 참고합니다. 없어도 화면은 뜨지만, 넣는 게 예의이자 표준입니다.

### `<head>` vs `<body>` — 이게 핵심

HTML 문서는 항상 **두 덩어리**로 나뉩니다. 이 구분이 처음엔 헷갈리지만 아주 중요합니다.

- **`<head>`** — **화면에 보이지 않는** 정보를 넣는 곳. 문서의 "설정"이라고 생각하세요. 예: 문서 제목, 문자 인코딩, 나중엔 CSS 연결, 검색용 설명 등.
- **`<body>`** — **화면에 실제로 보이는** 내용이 들어가는 곳. 제목·문단·이미지·버튼 등 눈에 보이는 건 전부 여기.

기억법: **head = 머릿속(안 보이는 생각/설정), body = 몸(밖으로 보이는 것).**

### `<meta charset="UTF-8" />`

`<head>` 안에 들어가는 설정입니다. **문자 인코딩**을 UTF-8로 지정하는데, 쉽게 말하면 **"한글·이모지 같은 글자를 안 깨지게 표시해줘"**입니다.

이 줄이 없으면 어떻게 될까요? 브라우저가 글자를 엉뚱하게 해석해서 `안녕`이 이렇게 깨질 수 있습니다:

```
ì•ˆë…•
```

한글을 쓰는 우리에겐 사실상 필수입니다. `meta`는 "이 문서에 대한 정보"라는 뜻이고, 내용이 없는 태그라 `/>`로 혼자 닫았습니다.

### `<title>내 블로그</title>`

`<head>` 안에 있죠? 그래서 화면 본문에는 안 보입니다. 대신 **브라우저 탭에 뜨는 이름**이 됩니다. 즐겨찾기에 저장할 때 이름도 이걸로 잡히고, 검색 결과에 제목으로도 쓰입니다.

### `<body>` 안의 `<h1>`과 `<p>`

드디어 화면에 보이는 부분입니다.

- `<h1>안녕, 블로그</h1>` — 페이지에서 가장 큰 제목
- `<p>이건 내가 만든 첫 웹페이지야.</p>` — 일반 문단

## 들여쓰기와 계층 — 왜 안쪽으로 밀어 쓸까

위 코드를 보면 `<head>` 안의 `<meta>`나 `<body>` 안의 `<h1>`이 **공백 몇 칸 안으로 밀려**서 적혀 있습니다. 이걸 **들여쓰기(indent)**라고 합니다.

들여쓰기는 **브라우저에겐 아무 의미도 없습니다.** 오직 **사람이 읽기 좋으라고** 하는 겁니다. 어떤 요소가 어떤 요소 "안에" 들어있는지(=부모-자식 관계)를 눈으로 바로 알 수 있거든요.

```
html
 ├─ head
 │   ├─ meta
 │   └─ title
 └─ body
     ├─ h1
     └─ p
```

`head`와 `body`는 `html`의 **자식**이고, `meta`·`title`은 `head`의 자식입니다. 이렇게 요소들이 상자 안의 상자처럼 겹겹이 담기는 걸 **중첩(nesting)**이라고 해요. 들여쓰기는 이 중첩 구조를 눈에 보이게 그려주는 습관입니다. 처음부터 들여쓰기를 잘 해두면 나중에 코드가 길어져도 안 헷갈립니다.

## 주석 — 나만 보는 메모

코드 사이에 "이건 뭐 하는 부분"이라고 메모를 남기고 싶을 때가 있습니다. HTML에서는 이렇게 씁니다.

```html
<!-- 이건 주석입니다. 화면에 안 보여요. -->
<h1>안녕, 블로그</h1>
```

`<!--`로 시작해서 `-->`로 끝나는 부분은 **브라우저가 무시**합니다. 화면에 안 나오고, 오직 코드를 읽는 사람만 봅니다. 나중에 "여기가 헤더", "여기부터 목록" 같은 표시를 남길 때 유용합니다.

## 브라우저에서 열어보기

가장 쉬운 방법: **탐색기에서 `index.html`을 더블클릭.** 기본 브라우저로 열립니다.

- 주소창을 보면 `file:///D:/Blog/index.html` 같은 게 떠 있습니다. 앞의 `file://`는 **"인터넷이 아니라 내 컴퓨터 파일을 열었다"**는 뜻이에요.
- 화면에 **"안녕, 블로그"**가 크게, 그 아래 문단이 보이면 성공입니다. 🎉

### 개발자 도구 살짝 구경하기

브라우저에서 **F12**(또는 마우스 우클릭 → 검사)를 눌러보세요. 화면 옆/아래에 코드 같은 게 잔뜩 뜨는 창이 열립니다. 이게 **개발자 도구**예요. 지금은 자세히 몰라도 되지만, "Elements(요소)" 탭을 보면 방금 우리가 쓴 `<h1>`, `<p>`가 그대로 있는 게 보입니다. 웹은 이렇게 **모두에게 코드가 열려 있습니다.** (그래서 나중에 "정적 사이트는 소스를 숨길 수 없다"는 말이 나오는 거예요.) 다 봤으면 F12를 다시 눌러 닫으세요.

> 참고: 나중에 자바스크립트가 다른 파일을 불러오기 시작하면 이 더블클릭(`file://`) 방식은 보안 때문에 일부 기능이 막힙니다. 그때 간단한 로컬 서버로 여는 법을 알려드릴게요. 지금 단계에선 더블클릭으로 충분합니다.

## 직접 만져보며 익히기

개념은 손으로 만져봐야 붙습니다. `<body>` 안에 아래를 하나씩 추가하고, 저장(Ctrl+S) → 브라우저 새로고침(F5)하며 결과를 확인해보세요.

```html
<h2>제목 크기 비교</h2>
<h3>이건 h3</h3>

<p>문단 안에서 <strong>이 부분은 굵게</strong>, <em>이 부분은 기울임</em>.</p>

<h2>내가 배운 것</h2>
<ul>
  <li>웹페이지는 사실 그냥 파일이다</li>
  <li>HTML은 뼈대를 만든다</li>
  <li>head는 설정, body는 보이는 내용</li>
</ul>

<h2>순서 있는 목록</h2>
<ol>
  <li>VS Code로 파일을 만든다</li>
  <li>코드를 쓴다</li>
  <li>브라우저로 연다</li>
</ol>

<p><a href="https://developer.mozilla.org/ko/">MDN 문서 보러 가기</a></p>
```

새로 나온 것들:

- `<h2>`, `<h3>` — h1보다 작은 제목들. 제목 크기 차이를 눈으로 확인해보세요.
- `<strong>` — 굵게(중요 강조), `<em>` — 기울임(emphasis)
- `<ol>` — ordered list. 자동으로 1, 2, 3 번호가 매겨지는 목록
- `<a href="...">` — 링크. 눌러보면 실제로 이동합니다

여기서 앞으로 계속 반복할 리듬을 몸에 익히세요:

> **코드 수정 → 저장(Ctrl+S) → 브라우저 새로고침(F5) → 결과 확인.**

이 짧은 순환이 웹 개발의 기본 박자입니다.

## 자주 나는 실수 (막히면 여기부터)

- **한글이 깨져 보인다** → `<meta charset="UTF-8" />`가 `<head>` 안에 제대로 있는지 확인.
- **바꿨는데 화면이 그대로다** → 저장(Ctrl+S)을 안 했거나(파일명 옆 ● 확인), 브라우저 새로고침(F5)을 안 한 경우. 둘 다 확인.
- **태그를 안 닫았다** → `<p>`만 쓰고 `</p>`를 빠뜨리면 그 아래 내용까지 이상하게 딸려 들어갑니다. 여는 태그가 있으면 닫는 태그도 짝을 맞추세요. (`<meta />` 같은 혼자 닫는 태그는 예외)
- **꺾쇠나 슬래시 오타** → `<h1>`을 `<h1`이나 `< h1>`처럼 쓰면 태그로 인식이 안 됩니다. 공백·철자 그대로.
- **파일 이름이 `index.html`이 아님** → `index.txt`, `index.html.txt`처럼 확장자가 잘못되면 브라우저가 웹페이지로 안 엽니다. VS Code에서 파일 이름을 다시 확인하세요.
- **파일을 엉뚱한 폴더에 만들었다** → 반드시 `Blog` 폴더 안에 있어야 다음 편들과 이어집니다.

## 정리

- 웹페이지는 신비한 게 아니라 **그냥 `.html` 파일**이고, 브라우저는 그걸 그림으로 그려주는 프로그램이다.
- HTML은 **구조(뼈대)**를 만드는 언어이고, **태그**로 이루어진다. 여는 태그 + 내용 + 닫는 태그 = **요소**.
- 태그에는 **속성**(옵션)을 붙일 수 있다.
- 문서는 항상 **head(안 보이는 설정)**와 **body(보이는 내용)**로 나뉜다.
- **들여쓰기·주석**은 브라우저가 아니라 사람을 위한 것.
- 리듬은 **저장 → 새로고침 → 확인.**

뼈대가 섰습니다. 다음 편(03)에서는 **CSS**로 색·글꼴·여백을 입혀서, 이 밋밋한 흑백 페이지를 블로그다운 모습으로 바꿉니다.
