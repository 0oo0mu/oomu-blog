# 웹에서 게시·수정·삭제 + 비밀번호 잠금

18편 에디터는 파일로 저장만 했습니다. 이번 편에서는 에디터에서 **GitHub에 바로 올리고(게시), 고치고(수정), 지우는(삭제)** 기능과, 이 위험한 기능을 **비밀번호로 잠그는** 보안을 붙입니다.

## GitHub API로 글 올리기(게시)

GitHub은 **API**를 제공해서, 웹페이지에서 코드로 파일을 커밋할 수 있습니다. 파일 하나를 만들거나 고치는 건 이 요청이에요.

```javascript
async function publish(filePath, content, token, owner, repo, branch) {
  const headers = {
    'Authorization': `Bearer ${token}`,
    'Accept': 'application/vnd.github+json',
  };
  const api = `https://api.github.com/repos/${owner}/${repo}/contents/${filePath}`;

  // 이미 있는 파일이면 SHA(파일 지문)를 먼저 조회 (수정 시 필요)
  let sha = null;
  const get = await fetch(`${api}?ref=${branch}`, { headers });
  if (get.ok) sha = (await get.json()).sha;

  // PUT = 파일 생성/수정
  const res = await fetch(api, {
    method: 'PUT',
    headers,
    body: JSON.stringify({
      message: sha ? `글 수정: ${filePath}` : `새 글: ${filePath}`,
      content: btoa(unescape(encodeURIComponent(content))), // UTF-8 → Base64
      branch,
      ...(sha ? { sha } : {}),
    }),
  });
  if (!res.ok) throw new Error((await res.json()).message);
}
```

- **토큰(PAT)** — GitHub이 발급하는 무작위 비밀번호 같은 것. 이게 있어야 API로 커밋할 수 있습니다. (GitHub → Settings → Developer settings → Personal access tokens에서 `repo` 권한으로 발급.)
- **SHA** — 기존 파일을 **수정**하려면 그 파일의 현재 버전 지문(sha)을 함께 보내야 합니다. 그래서 먼저 GET으로 조회하고, 있으면 수정, 없으면 새로 생성.
- **Base64** — GitHub API는 파일 내용을 Base64(글자로 인코딩한 형식)로 받습니다. `btoa(unescape(encodeURIComponent(...)))`는 한글도 안 깨지게 UTF-8 → Base64로 바꾸는 공식이에요.
- 커밋이 올라가면, 우리가 만들 **자동 배포(20편)**가 CI에서 build를 돌려 사이트에 반영합니다.

**삭제**는 거의 같습니다. SHA를 조회한 뒤 `method: 'DELETE'`로 요청하면 파일이 지워져요.

**수정**은 글 화면에 "✏️ 수정" 버튼을 달아 `editor.html?edit=글경로`로 열고, 그 글을 fetch해 폼에 채운 뒤(제목·본문·카테고리…), 같은 경로로 다시 게시(PUT+sha)하면 덮어써집니다.

## 위험 — 토큰을 어떻게 보관하나

여기서 큰 문제가 있습니다. **저장소가 public이라 코드가 다 공개됩니다.** 토큰을 코드에 적으면 누구나 보고 내 저장소를 조작할 수 있어요. 절대 안 됩니다.

또, 게시 버튼이 아무에게나 열려 있으면 곤란하죠(방문자는 못 쓰게 해야 함).

해결책 두 가지를 합칩니다.

1. 토큰은 **코드에 넣지 않고**, 내 **브라우저에만** 저장한다.
2. 그마저도 평문이 아니라, **내가 정한 비밀번호로 암호화**해서 저장한다. 그리고 게시하려면 그 비밀번호로 잠금을 풀어야 한다.

## 비밀번호로 토큰 암호화 — Web Crypto

브라우저에는 **Web Crypto**라는 암호화 도구가 내장돼 있습니다. 비밀번호로부터 열쇠를 만들어(PBKDF2), 그 열쇠로 토큰을 암호화(AES-GCM)합니다.

```javascript
// 비밀번호 → 암호 열쇠
async function deriveKey(password, salt) {
  const base = await crypto.subtle.importKey(
    'raw', new TextEncoder().encode(password), 'PBKDF2', false, ['deriveKey']);
  return crypto.subtle.deriveKey(
    { name: 'PBKDF2', salt, iterations: 150000, hash: 'SHA-256' },
    base, { name: 'AES-GCM', length: 256 }, false, ['encrypt', 'decrypt']);
}

// 토큰 암호화해서 localStorage에 저장
async function encryptToken(token, password) {
  const salt = crypto.getRandomValues(new Uint8Array(16));
  const iv   = crypto.getRandomValues(new Uint8Array(12));
  const key  = await deriveKey(password, salt);
  const ct   = await crypto.subtle.encrypt({ name: 'AES-GCM', iv }, key,
                    new TextEncoder().encode(token));
  localStorage.setItem('gh_token_enc', JSON.stringify({
    salt: b64(salt), iv: b64(iv), ct: b64(new Uint8Array(ct)),
  }));
}

// 비밀번호로 복호화 (틀리면 예외 발생 → 잠금 해제 실패)
async function decryptToken(password) {
  const { salt, iv, ct } = JSON.parse(localStorage.getItem('gh_token_enc'));
  const key = await deriveKey(password, unb64(salt));
  const pt  = await crypto.subtle.decrypt({ name: 'AES-GCM', iv: unb64(iv) }, key, unb64(ct));
  return new TextDecoder().decode(pt);
}
```

- **최초 1회**: GitHub 토큰을 한 번 붙여넣고 내가 쓸 비밀번호를 정하면 → `encryptToken`이 토큰을 그 비번으로 암호화해 저장. (비번 자체는 저장 안 함.)
- **이후**: 비밀번호만 입력하면 → `decryptToken`이 토큰을 복원. 비번이 틀리면 복호화가 실패(예외)하므로 잠금이 안 풀립니다.

**PBKDF2**는 비밀번호를 15만 번 반복 계산해 열쇠를 만들어(무차별 대입을 느리게), **AES-GCM**은 실제 암호화 방식입니다. 이 둘 다 브라우저 내장이라 라이브러리가 필요 없어요.

## 세션 — 10분 유지

매번 비번을 넣으면 번거로우니, 한 번 풀면 **10분간 유지**합니다. 복호화한 토큰을 만료 시각과 함께 `sessionStorage`에 넣고, 게시할 때 아직 유효하면 그 토큰을 씁니다. 입력·활동이 있으면 시간을 연장하고, 10분 지나면 다시 잠급니다.

```javascript
function saveSession(token) {
  sessionStorage.setItem('editor_session',
    JSON.stringify({ token, until: Date.now() + 10*60*1000 }));
}
function getToken() {
  const s = JSON.parse(sessionStorage.getItem('editor_session') || 'null');
  if (!s || Date.now() > s.until) return null; // 만료
  return s.token;
}
```

게시 코드는 토큰을 `getToken()`으로 가져옵니다. 잠금이 안 풀렸으면 `null`이라 게시가 막혀요. 방문자는 토큰도, 비번도 없으니 아무것도 못 올립니다. 사이트가 정적 파일이라 서버를 통해 조작할 여지도 없고요.

## 정리

- **GitHub API**(PUT/DELETE)로 에디터에서 글을 게시·수정·삭제할 수 있다. 수정·삭제엔 파일 **SHA**가 필요하고, 내용은 **Base64**로 보낸다.
- public 저장소라 **토큰을 코드에 넣으면 안 된다.** 토큰은 브라우저에만, 그것도 **비밀번호로 암호화(Web Crypto)**해 저장한다.
- 잠금을 풀면 토큰이 **세션(10분)**에 유지되고, 방문자는 비번이 없어 게시할 수 없다.

다음 편(20, 마지막)에서는 배포를 자동화합니다. `build.js`를 확장해 sitemap·robots·config를 만들고, **GitHub Actions**로 push하면 자동으로 빌드·배포되게 해서 시리즈를 마무리합니다.
