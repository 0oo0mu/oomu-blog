# 게시·수정·삭제 + 비밀번호 잠금 (전체 코드 해설)

18편 에디터는 파일로 저장만 했습니다. 이번 편에서 **GitHub에 바로 올리고(게시)·고치고(수정)·지우는(삭제)** 기능과, 이 위험한 기능을 **비밀번호로 잠그는** 보안(editor-auth.js)을 전체 코드로 봅니다.

## GitHub 설정 읽기

먼저 게시에 필요한 값(토큰·저장소)을 어디서 가져오는지 봅니다.

```javascript
  _getGitHubSettings() {
    return {
      // 토큰은 잠금 해제된 세션(EditorAuth)에서 가져옴 (평문 저장 안 함)
      token:  (window.EditorAuth && window.EditorAuth.getToken()) || localStorage.getItem('gh_token') || '',
      owner:  localStorage.getItem('gh_owner')  || '0oo0mu',
      repo:   localStorage.getItem('gh_repo')   || 'oomu-blog',
      branch: localStorage.getItem('gh_branch') || 'main',
    };
  },
```

핵심: **토큰은 `window.EditorAuth.getToken()`에서** 옵니다. 이건 아래에서 만들 잠금 모듈이 비밀번호로 풀어 세션에 담아둔 토큰이에요. 잠금이 안 풀렸으면 `null`이라 게시가 막힙니다. owner/repo/branch는 저장소 정보(비밀 아님)로 localStorage에 둡니다.

## 게시 — _publishToGitHub

```javascript
  async _publishToGitHub() {
    const { token, owner, repo, branch } = this._getGitHubSettings();
    if (!token || !owner || !repo) { showToast('⚙️ 먼저 GitHub 설정을 입력하세요'); return; }

    const relPath = this._resolveRelPath();      // 카테고리/제목.md (18편)
    if (!relPath) { showToast('📝 제목을 입력하세요'); return; }
    const filePath = `posts/${relPath}`;
    const content  = this._buildFileContent();   // Front Matter + 본문
    const title    = document.getElementById('fmTitle')?.value.trim() || '새 글';

    const btn = document.getElementById('publishBtn');
    const origText = btn?.innerHTML;
    if (btn) { btn.disabled = true; btn.innerHTML = '⏳ 게시 중...'; }

    try {
      const headers = {
        'Authorization': `Bearer ${token}`,
        'Accept': 'application/vnd.github+json',
        'X-GitHub-Api-Version': '2022-11-28',
      };
      const apiBase = `https://api.github.com/repos/${owner}/${repo}/contents/${filePath}`;

      // 기존 파일이면 SHA 조회 (수정 시 필요)
      let sha = null;
      const getRes = await fetch(`${apiBase}?ref=${branch}`, { headers });
      if (getRes.ok) sha = (await getRes.json()).sha;

      // PUT = 파일 생성/수정
      const body = {
        message: sha ? `글 수정: ${title}` : `새 글: ${title}`,
        content: btoa(unescape(encodeURIComponent(content))), // UTF-8 → Base64
        branch,
      };
      if (sha) body.sha = sha;

      const putRes = await fetch(apiBase, { method: 'PUT', headers, body: JSON.stringify(body) });
      if (!putRes.ok) throw new Error((await putRes.json()).message || `HTTP ${putRes.status}`);

      showToast(`🚀 ${sha ? '수정' : '게시'} 완료! 1~2분 내 배포됩니다.`, 5000);
    } catch (err) {
      if (err.message.includes('Bad credentials')) showToast('❌ 토큰이 잘못되었습니다.');
      else showToast('❌ 게시 실패: ' + err.message);
    } finally {
      if (btn) { btn.disabled = false; btn.innerHTML = origText; }
    }
  },
```

- **토큰(PAT)** — GitHub이 발급하는 무작위 비밀번호. `Authorization: Bearer 토큰` 헤더로 인증합니다.
- **SHA** — 기존 파일을 **수정**하려면 그 파일의 현재 지문(sha)이 필요합니다. 그래서 먼저 GET으로 조회해, 있으면 수정(PUT+sha), 없으면 새로 생성(PUT). 같은 경로면 자동으로 "수정"이 되는 거죠(18편의 `?edit=`이 경로를 채워둠).
- **Base64** — GitHub API는 파일 내용을 Base64로 받습니다. `btoa(unescape(encodeURIComponent(...)))`는 한글도 안 깨지게 UTF-8 → Base64로 바꾸는 표준 공식이에요.
- 커밋이 올라가면 **자동 배포(20편)**가 CI에서 빌드해 사이트에 반영합니다.
- `try/catch/finally`로 실패해도 버튼이 다시 살아나게(로딩 상태 해제) 처리했습니다.

## 삭제 — _deleteFromGitHub

```javascript
  async _deleteFromGitHub() {
    const { token, owner, repo, branch } = this._getGitHubSettings();
    if (!token || !owner || !repo) { showToast('⚙️ 먼저 GitHub 설정을 입력하세요'); return; }

    const manual = document.getElementById('filenameInput')?.value.trim();
    if (!manual) { showToast('🗑️ 삭제할 글이 없습니다.'); return; }
    const relPath  = manual.endsWith('.md') ? manual : manual + '.md';
    const filePath = `posts/${relPath}`;
    if (!confirm(`정말 삭제할까요?\n\n${filePath}`)) return;

    try {
      const headers = {
        'Authorization': `Bearer ${token}`,
        'Accept': 'application/vnd.github+json',
        'X-GitHub-Api-Version': '2022-11-28',
      };
      const apiBase = `https://api.github.com/repos/${owner}/${repo}/contents/${filePath}`;
      const getRes = await fetch(`${apiBase}?ref=${branch}`, { headers });
      if (getRes.status === 404) { showToast('❌ 저장소에 그 파일이 없습니다.'); return; }
      if (!getRes.ok) throw new Error(`HTTP ${getRes.status}`);
      const { sha } = await getRes.json();

      const delRes = await fetch(apiBase, {
        method: 'DELETE', headers,
        body: JSON.stringify({ message: `글 삭제: ${relPath}`, sha, branch }),
      });
      if (!delRes.ok) throw new Error((await delRes.json()).message);

      showToast('🗑️ 삭제 완료! 목록으로 이동합니다.', 4000);
      setTimeout(() => { window.location.href = 'index.html'; }, 1500);
    } catch (err) {
      showToast('❌ 삭제 실패: ' + err.message);
    }
  },
```

삭제도 거의 같습니다. 파일의 SHA를 조회한 뒤 `method: 'DELETE'`로 요청합니다. 삭제 버튼은 18편에서 봤듯 **수정으로 불러온 글에서만** 보여요. 실수 방지를 위해 `confirm`으로 한 번 더 확인하고, 지운 뒤 목록으로 돌아갑니다. (git 기록엔 남아 있어 복구는 가능합니다.)

## 왜 잠금이 필요한가

문제가 있습니다. **저장소가 public이라 코드가 다 공개**됩니다. 토큰을 코드에 적으면 누구나 보고 내 저장소를 조작할 수 있어요. 또 게시 버튼이 아무에게나 열려 있으면 안 되죠. 해결책:

1. 토큰은 **코드에 넣지 않고** 내 **브라우저에만** 저장한다.
2. 그마저도 평문이 아니라 **내가 정한 비밀번호로 암호화**한다. 게시하려면 그 비번으로 잠금을 풀어야 한다.

이제 이걸 하는 `editor-auth.js`를 만듭니다.

## editor-auth.js — 암호화 (Web Crypto)

브라우저 내장 **Web Crypto**로, 비밀번호에서 열쇠를 만들어(PBKDF2) 토큰을 암호화(AES-GCM)합니다.

```javascript
const SESSION_MIN = 10;                 // 세션 유지(분)
const LS_ENC   = 'gh_token_enc';        // localStorage: 암호화된 토큰
const SS_SESS  = 'editor_session';      // sessionStorage: { token, until }

const b64   = (u8) => btoa(String.fromCharCode(...u8));
const unb64 = (s)  => Uint8Array.from(atob(s), c => c.charCodeAt(0));

const EditorAuth = {
  // 비밀번호 → AES 열쇠
  async _deriveKey(password, salt) {
    const base = await crypto.subtle.importKey(
      'raw', new TextEncoder().encode(password), 'PBKDF2', false, ['deriveKey']);
    return crypto.subtle.deriveKey(
      { name: 'PBKDF2', salt, iterations: 150000, hash: 'SHA-256' },
      base, { name: 'AES-GCM', length: 256 }, false, ['encrypt', 'decrypt']);
  },

  // 토큰 암호화 → localStorage 저장
  async _encrypt(token, password) {
    const salt = crypto.getRandomValues(new Uint8Array(16));
    const iv   = crypto.getRandomValues(new Uint8Array(12));
    const key  = await this._deriveKey(password, salt);
    const ct   = await crypto.subtle.encrypt({ name: 'AES-GCM', iv }, key,
                      new TextEncoder().encode(token));
    localStorage.setItem(LS_ENC, JSON.stringify({
      salt: b64(salt), iv: b64(iv), ct: b64(new Uint8Array(ct)),
    }));
  },

  // 비밀번호로 복호화 (틀리면 예외 → 잠금 실패)
  async _decrypt(password) {
    const raw = localStorage.getItem(LS_ENC);
    if (!raw) return null;
    const { salt, iv, ct } = JSON.parse(raw);
    const key = await this._deriveKey(password, unb64(salt));
    const pt  = await crypto.subtle.decrypt({ name: 'AES-GCM', iv: unb64(iv) }, key, unb64(ct));
    return new TextDecoder().decode(pt);
  },

  hasToken() { return !!localStorage.getItem(LS_ENC); },
  reset()    { localStorage.removeItem(LS_ENC); this.lock(); },
```

- **PBKDF2** — 비밀번호를 15만 번 반복 계산해 열쇠를 만듭니다. 반복이 많을수록 무차별 대입(비번 하나씩 시도)이 느려져 안전해요. `salt`(무작위 값)를 섞어 같은 비번이라도 매번 다른 열쇠가 나오게 합니다.
- **AES-GCM** — 실제 암호화 방식. `iv`(초기화 벡터, 무작위)와 함께 토큰을 암호문(`ct`)으로 만듭니다.
- 저장하는 건 `{salt, iv, ct}`뿐 — **비밀번호도, 평문 토큰도 저장 안 합니다.** 비번이 틀리면 `_decrypt`가 예외를 던져 잠금이 안 풀려요.
- `b64`/`unb64`는 바이트 배열을 문자열(localStorage 저장용)로 바꾸는 헬퍼입니다.

## 세션 — 10분 유지 (슬라이딩)

```javascript
  _saveSession(token) {
    sessionStorage.setItem(SS_SESS, JSON.stringify({
      token, until: Date.now() + SESSION_MIN * 60 * 1000,
    }));
  },
  _session() {
    const raw = sessionStorage.getItem(SS_SESS);
    if (!raw) return null;
    const s = JSON.parse(raw);
    if (Date.now() > s.until) { sessionStorage.removeItem(SS_SESS); return null; } // 만료
    return s;
  },
  getToken()   { return this._session()?.token || null; },
  isUnlocked() { return !!this._session(); },
  lock()       { sessionStorage.removeItem(SS_SESS); },
  extend()     { const s = this._session(); if (s) this._saveSession(s.token); }, // 활동 시 연장
```

한 번 풀면 **10분간** 토큰을 `sessionStorage`에 유지합니다(만료 시각과 함께). `getToken()`이 그 토큰을 돌려주고, 만료됐으면 `null`. `extend()`는 사용자 활동이 있을 때 시간을 다시 10분으로 늘려(슬라이딩) 글 쓰는 중에 안 잠기게 합니다.

## 잠금 해제 / 최초 설정

```javascript
  // 비밀번호 또는 토큰 원문 둘 다 허용
  async unlock(input) {
    const val = (input || '').trim();
    if (!val) throw new Error('입력이 비어 있음');

    // ① 비밀번호로 저장된 토큰 복호화 시도
    if (this.hasToken()) {
      try {
        const token = await this._decrypt(val);
        if (token) { this._saveSession(token); return token; }
      } catch (_) {}
    }
    // ② 입력이 토큰 원문이면 GitHub로 검증 후 사용
    if (this._looksLikeToken(val) && await this._validateToken(val)) {
      this._saveSession(val); return val;
    }
    throw new Error('인증 실패');
  },

  _looksLikeToken(v) { return /^(ghp_|github_pat_|gho_|ghs_|ghu_)/.test(v) || v.length >= 40; },
  async _validateToken(token) {
    try {
      const res = await fetch('https://api.github.com/user', {
        headers: { 'Authorization': `Bearer ${token}`, 'Accept': 'application/vnd.github+json' } });
      return res.ok;
    } catch { return false; }
  },

  // 최초 1회: 토큰 + 내가 정한 비번 → 암호화 저장
  async setup(token, password) {
    await this._encrypt(token, password);
    if (!localStorage.getItem('gh_owner'))  localStorage.setItem('gh_owner', '0oo0mu');
    if (!localStorage.getItem('gh_repo'))   localStorage.setItem('gh_repo', 'oomu-blog');
    if (!localStorage.getItem('gh_branch')) localStorage.setItem('gh_branch', 'main');
    this._saveSession(token);
  },
```

- **`unlock(input)`** — 입력을 두 가지로 받아들입니다. ① 비밀번호면 저장된 토큰을 복호화. ② 그게 안 되고 입력이 토큰 형태면(`ghp_...` 또는 40자↑) GitHub API(`/user`)로 진짜 유효한 토큰인지 검증 후 사용. 그래서 비번을 잊어도 토큰으로, 새 PC에서도 토큰만 있으면 들어갈 수 있어요.
- **`setup`** — 최초 1회, 토큰을 붙여넣고 비번을 정하면 암호화해 저장하고 저장소 기본값을 세팅합니다.

## 잠금 화면 & 세션바

init에서 전체화면 잠금 오버레이와 우상단 세션바를 만들어 붙이고, 활동을 감지해 세션을 연장합니다(전체 코드는 부록 D 참고). 핵심 흐름만 보면:

```javascript
  init() {
    if (!window.crypto?.subtle) { alert('https/localhost에서 열어주세요'); return; }
    this._injectOverlay();   // 잠금 화면(비번 입력 / 최초 설정) DOM 삽입
    this._injectSessionBar();// 우상단 남은시간·연장·잠금 바
    this._bindActivity();    // 입력·클릭 시 세션 연장(슬라이딩)
    this._gate();            // 세션 있으면 열고, 없으면 잠금 화면 표시
    this._tickTimer = setInterval(() => this._tick(), 1000); // 1초마다 남은시간 갱신
  },

  _gate() { this.isUnlocked() ? this._reveal() : this._showOverlay(); },
```

- **잠금 화면**은 저장된 토큰이 있으면 "비밀번호 입력", 없으면 "최초 설정(토큰+비번)" 모드를 보여줍니다. 방문자는 토큰도 비번도 없으니 아무것도 못 하고요.
- **세션바**는 남은 시간을 보여주고 [연장]/[잠금] 버튼을 제공합니다. 입력·클릭이 있으면 자동 연장, 10분 지나면 다시 잠깁니다.
- `window.crypto.subtle`은 **보안 컨텍스트**(https 또는 localhost)에서만 동작합니다. `file://`로 열면 안 되니 안내를 띄워요.

## 연결 — app-editor.js

```javascript
import Theme      from './core/theme.js';
import Accent     from './core/accent.js';
import Editor     from './modules/editor.js';
import EditorAuth from './modules/editor-auth.js';

Theme.init();
Accent.init();
Editor.init();
EditorAuth.init();   // 에디터를 잠금으로 보호
```

에디터 진입점에서 `EditorAuth.init()`을 부르면, 에디터 위에 잠금 화면이 씌워져 비번을 풀어야 쓸 수 있습니다. 게시 코드의 `_getGitHubSettings`가 `window.EditorAuth.getToken()`으로 토큰을 가져오니, 잠금을 안 풀면 게시가 원천적으로 막힙니다.

## 정리

- **GitHub API**(PUT/DELETE)로 게시·수정·삭제. 수정·삭제엔 파일 **SHA**, 내용은 **Base64**.
- public 저장소라 **토큰을 코드에 넣으면 안 된다.** 토큰은 브라우저에만, **비밀번호로 암호화(PBKDF2+AES-GCM)**해 저장.
- 잠금을 풀면 토큰이 **세션(10분, 슬라이딩)**에 유지되고, 방문자는 비번이 없어 게시 불가.
- `unlock`은 비밀번호 또는 토큰 원문 둘 다 허용.

이걸로 CRUD(작성·읽기·수정·삭제)와 보안까지 완성됐습니다. 다음 편(20)에서 배포 자동화로 시리즈를 마무리합니다. (이미 20편이 있다면, 이제 본편 16~19가 전체 코드 해설로 채워졌으니 부록과 함께 **완전한 재현 가이드**가 됩니다.)
